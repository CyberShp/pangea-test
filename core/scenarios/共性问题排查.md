# 场景作业流程：共性问题排查

> 执行主体：primary（开发分析工作流） ｜ 新编排（M1/M3 新搭，非九步继承）｜ 模式：**深度型**
> 上游：[architecture.md](../../docs/architecture.md) §6（obligation/range 分片并发 + 断点恢复）、§2.3.2（mr-reader）、§2.3.1（analysis-worker 作为码搜引擎）｜ [requirements.md](../../docs/requirements.md) R-8.1、R-10.1
> **纪律**：本场景的编排逻辑（定模式 → 搜同类结构 → 归纳共性风险 → 批量用例）是 M1 新搭的调度骨架，**可写实**——不涉及 Codetalks 内网专属分析话术，故本文无迁移占位。透镜/方法论/模板仍走既有知识库引用。

---

## 1. 场景定位

输入一批 MR 或一组现象描述，从中**抽取一个可搜索的"缺陷模式"**（如某种漏释放写法、某种未校验的入参、某种状态判断遗漏），然后在代码库里**横向搜同类结构**，把"一个缺陷"放大成"一类隐患"，最后批量产出针对同类隐患的黑盒用例。核心是"由点及面"——不是深钻单一对象（那是专项风险分析），而是广搜同一模式的所有落点。

## 2. 输入（前置到 primary 收集）

- **一批 MR 链接**（每个经 mr-reader 取摘要）**或** 用户直接给的**现象描述**（一段自然语言，如"多个连接超时后不释放缓冲"）。
- **源码路径**：横向搜码需要，按 R-8.4 先询问"是否基于源码分析"（该询问前置在 primary 完成）。
- **模式**：固定深度型（"排查一批/搜同类"命中深度型判据，见 `core/shared/调度规则.md` 二）。
- **任务 id**：`共性问题排查-<模式slug>-<日期>`（`模式slug` 取共性模式短名，规则见 `core/shared/调度规则.md` 三）。

## 3. 流程（编排步骤，写实）

1. **模式定义（由输入抽取"缺陷模式"）**：
   - 输入是 MR 批 → 对每个 MR 派 `mr-reader` 取 `mr_summary`，从各 `risk_hotspots` 中**归纳出共同的代码模式**（结构/写法/反模式），落为一句可搜索的"特征描述"。
   - 输入是现象描述 → primary 直接把现象翻译为代码特征模式（必要时先轻量读码定位一个样例锚点）。
   - 若共性模式恰好命中某个 DFX 透镜（资源泄漏/并发/超时恢复），**优先复用透镜"代码特征模式"栏**作为搜索指令，避免自造扫描规则漂移。
2. **横向搜码（analysis-worker 作码搜引擎）**：把上一步的特征模式作为扫描指令，obligation/range 分片并发 多个 `风险扫描` 实例覆盖不同目录/子模块——每个实例以特征模式 grep/阅读，命中点入证据包 `hits[]`（{位置, 命中特征, 风险机理}），未命中给 `immunity_note`。
   - 命中的透镜型模式：`context-pack(<子模块>, 风险扫描, 透镜=<X>)`；
   - 非透镜型的自定义结构模式：仍走 `风险扫描` 剧本，扫描指令由primary 在派发时以"特征描述"注入（剧本流程步骤②"以代码特征模式为扫描指令"支持此用法）。
3. **必要时补结构剧本**：某些命中点需确认是否真是隐患（如是否真有异常路径漏释放），对该点追派 `资源生命周期` / `异常传播` / `状态机提取` 坐实证据。
4. **obligation/range 分片并发**：按上述剧本/透镜/特征模式建立 immutable context packs，并发调用同一 `analysis-worker`，证据包落 `pangea-data/runs/<任务id>/`，manifest 登记（含各 `mr_summary` 条）。

## 3b. 与相邻场景的分工（防混淆）

| 场景 | 走向 | 一句话 |
|---|---|---|
| 共性问题排查（本场景）| 一个模式 → **横向搜多个落点** | 由点及面，广度优先 |
| 专项风险分析 | 一个对象+透镜 → **纵向深钻到用例级** | 由面及底，深度优先 |
| 模块全量分析 | 一个模块 → 全链路全透镜浅扫 | 系统性普查 |

> 输入常是 MR/问题单分析或 FST 逃逸复盘的产出（衔接见 §6 与 architecture §2.1）——即"复盘出一个模式后，回来搜同类"。

## 4. 深度模式 obligation/range 分片并发（步骤 2–3 并行）

primary 在一条消息内并行派发多个**只读** analysis-worker 实例横扫代码库不同区域——参见 architecture §6.1。搜码是本场景最耗时环节，并行显著降墙钟时间。

**证据包落盘（运行时职责）**：analysis-worker 只返回 strict `analysis_fragment`；运行时验证 obligation/range/receipt，创建并更新 `manifest.md`、把通过校验的 fragment 与模型贡献写盘——文件名 `共性问题排查-<模式slug>-<剧本>-<序号>.md`（schema 见 `core/shared/证据包schema.md` §4.1）；primary 只消费固定工件。
**断点恢复**：启动前先读 `manifest.md`——`complete` 跳过、`partial` 按 `resume_hint` 续挖（architecture §6.2）。目录已存在时先问用户"续跑还是重挖"。
**并发降级**：analysis-worker 并发上限/返回体量待实测（T-3），超限则分批串行，语义不变。

## 5. 收尾门

1. **归纳共性风险**：primary 收齐全部 `code_evidence` → 合并所有 `hits[]` → 归纳为**共性风险清单**（同一模式的全部落点 + 风险机理 + 严重度分级），用 `core/templates/SFMEA.md` 承载（每行一个落点或一类落点）。
2. **批量用例**：对共性风险清单用 `core/methods/_selector.md` 选法推导**批量针对性用例**（同模式多落点可共享用例骨架、按落点参数化），落 `core/templates/黑盒用例.md`；用例 `关联风险` 栏回指共性模式与具体落点。
3. **auditor 复核**：Task 派 `auditor`（独立上下文，只审不改）→ `audit_opinion`（四组 checks：溯源/黑盒可执行性/**覆盖=同类落点是否搜全**/格式）。覆盖维度重点审"横向搜码广度"（免疫说明是否覆盖已扫区域）。
4. **覆盖审计 PASS** 才算完成；FAIL/CONCERNS → 按 `required_actions` 结构化回挖（补扫遗漏区域，manifest `audit.rounds` +1）。**回挖 ≤ 2 轮**，仍不过则带 CONCERNS 出报告、首页标未决项，交用户裁决。
5. **产出**：报告章节骨架：输入与共性模式定义 → 横向搜码范围 → 共性风险清单（落点全集）→ 批量用例 → 覆盖审计结论 → **待用户确认**。
6. **回填询问**：R-7.4"是否回填知识"（共性模式可回填透镜"代码特征模式"/"典型历史缺陷"栏）写入报告末尾"待用户确认"节，不在对话内提问（T-6）。

## 6. 场景衔接（供 primary 推荐）
