# 场景作业流程：专项风险分析

> 执行主体：primary（开发分析工作流） ｜ 对应 Codetalks 专项风险分析流程 ｜ 模式：**深度型**
> 上游：[architecture.md](../../docs/architecture.md) §6（obligation/range 分片并发 + 断点恢复）、§8（深度型时序）｜ [requirements.md](../../docs/requirements.md) R-6.2（透镜双消费）、R-10.1
> **纪律**：本文只写"编排骨架"——primary 该按什么步骤单透镜深钻。专项风险分析的具体研判话术（8 大风险主题的分析内功心法：泄漏/耗尽/计数翻转/并发/超时恢复/协议安全/性能退化/HA）是 Codetalks 内部资产，一律留 `<!-- 待迁移 M-7a -->` 占位，**不得凭简介重写**。

## 1. 场景定位

选定**一个对象 + 一个透镜**，把该透镜**深钻到用例级**——这是 R-6.2"透镜双消费"的**深钻模式**，与模块全量分析的**浅扫模式**成对：

| | 浅扫（模块全量分析 §5）| 深钻（本场景）|
|---|---|---|
| 透镜数 | 全部种子透镜逐个过一遍 | **单透镜**聚焦 |
| 深度 | 命中即记 SFMEA，广度优先 | 顺该透镜风险机理**穷尽变体**，追到每个失效路径 |
| 产出 | 全透镜 SFMEA 概览 | 该维度**完备用例集** |

即"一个维度、一个对象、挖到底"。适合对全量分析暴露的高危项、或某次故障暴露的专项维度做深度补强。

## 2. 输入（前置到 primary 收集）

- **分析对象**（模块/函数/状态机等短名）+ **透镜**（DFX 维度，如 资源泄漏 / 并发 / 超时恢复；M1 种子三透镜之外的 M3 补）。
- **源码路径**：按 R-8.4 先询问"是否基于源码分析"（前置在 primary 完成）。
- **模式**：固定深度型。
- **任务 id**：`专项风险分析-<对象slug>-<日期>`（规则见 `core/shared/调度规则.md` 三）。

## 3. 深钻编排骨架

> 深钻不是"多派几个风险扫描"，而是**顺单透镜的风险机理逐层展开变体**，每层坐实证据、直到能推出用例。下表列每步调度什么、产出什么；各风险主题的研判内功心法留占位。

<!-- 待迁移 M-7a：注意——下方编排表是 M1 新搭的调度骨架，【保留勿删】；内网迁移是把 Codetalks 专项风险分析原文的 8 主题研判话术/失效变体清单/用例映射细则**补充**到"深钻研判"之下（逐字继承），并把 8 主题逐一映射为透镜库条目（种子已覆盖 泄漏/并发/超时恢复 三项），不是整块替换本表 -->

1. **锁定透镜与对象**：primary 按裸名经 `core/lenses/_index.md` 解析透镜路径并加载，取其"代码特征模式"+"典型历史缺陷"+"失效模式"栏作为深钻起点。
2. **风险扫描（首层命中）**：派 `context-pack(<对象>, 风险扫描, 透镜=<X>)`，以透镜"代码特征模式"扫描对象，产出首层 `hits[]`（该维度所有初始命中点）。
3. **深钻展开（每个命中点顺机理追变体）**：对每个命中点，按该透镜的风险机理追**失效变体**——追派结构剧本坐实证据：
   - 泄漏类 → `资源生命周期`（异常路径漏释放/双重释放变体）；
   - 并发类 → `并发上下文识别`（共享数据/锁边界/竞争窗口变体）；
   - 超时恢复类 → `超时重试盘点` + `异常传播`（超时触发动作/重试上限/恢复路径变体）；
   - 涉及状态时序 → `状态机提取`（非法迁移/时序竞态变体）。<!-- 待迁移 M-7a：各主题该追哪些变体、追到什么粒度停，随专项风险原文继承 -->
4. **obligation/range 分片并发**：按上述剧本/透镜建立 immutable context packs，并发调用同一 `analysis-worker`，证据包落 `pangea-data/runs/<任务id>/`。

## 4. 深度模式 obligation/range 分片并发（步骤 2–3 并行）

运行时按独立 inventory/ledger 为首层扫描和各命中点建立 immutable obligations/ranges，绑定 context pack 哈希与 receipts 后并发调用同一 `analysis-worker`；首层完成后再按命中点批量展开结构剧本。

**证据包落盘（运行时职责）**：analysis-worker 只返回 strict `analysis_fragment`；运行时验证 obligation/range/receipt，创建并更新 `manifest.md`、把通过校验的 fragment 与模型贡献写盘——文件名 `专项风险分析-<对象slug>-<剧本>-<序号>.md`（schema 见 `core/shared/证据包schema.md` §4.1）；primary 只消费固定工件。
**断点恢复**：启动前先读 `manifest.md`——`complete` 跳过、`partial` 按 `resume_hint` 续挖（architecture §6.2）。目录已存在时先问用户"续跑还是重挖"。
**并发降级**：analysis-worker 并发上限/返回体量待实测（T-3），超限则分批串行，语义不变。

## 5. 收尾门

1. **汇总为专项 SFMEA**：primary 收齐 `code_evidence` → 把单透镜的全部失效变体归为深度 SFMEA（`core/templates/SFMEA.md`），失效机理栏统一引该透镜——**深度而非广度**：宁可这一维度穷尽，不旁涉其它透镜。
2. **推完备用例集**：对每个失效变体用 `core/methods/_selector.md` 选法推导用例，**目标是该维度的完备覆盖**（`状态转换`/`边界值分析` 等按变体特征选法），落 `core/templates/黑盒用例.md`；用例 `覆盖目标` 栏锚定"透镜 X 的失效变体集"，供 coverage 审计比对。
3. **auditor 复核**：Task 派 `auditor`（独立上下文，只审不改）→ `audit_opinion`（四组 checks：溯源/黑盒可执行性/**覆盖=单透镜失效变体是否穷尽**/格式）。coverage `dimension` 填该透镜维度。
4. **覆盖审计 PASS** 才算完成；FAIL/CONCERNS → 按 `required_actions` 回挖遗漏变体（manifest `audit.rounds` +1）。**回挖 ≤ 2 轮**，仍不过则带 CONCERNS 出报告、首页标未决项，交用户裁决。
5. **产出**：报告章节骨架：分析对象与透镜 → 首层命中 → 失效变体深钻（证据包引用）→ 专项 SFMEA → 完备用例集 → 覆盖审计结论 → **待用户确认**。
6. **回填询问**：R-7.4"是否回填知识"（重点回填该透镜"典型历史缺陷"栏）写入报告末尾"待用户确认"节，不在对话内提问（T-6）。
