## 1. 场景定位

对一个模块做系统性、全链路的黑盒测试分析，产出：主干/分支/状态/资源/异常结构 → SFMEA（全透镜浅扫）→ 黑盒场景 → 黑盒流程 → 黑盒用例 → 覆盖审计。是 primary 开发分析阶段的旗舰深度场景。

## 2. 输入（前置到 primary 收集）

- **源码路径**：按 R-8.4，**先询问用户"是否基于源码分析"**，是则索要源码路径（该询问前置在 primary 完成，见 §2.1 第 5 条）。
- **模式**：固定深度型（含"全量/系统性"关键词，见 `core/shared/调度规则.md` 二）。
- **任务 id**：primary 生成 `模块全量分析-<对象slug>-<日期>`（规则见 `core/shared/调度规则.md` 三）；primary 自举时按同一规则自生成。

## 4. 深度模式 obligation/range 分片并发（步骤 1–7 并行）

运行时依据独立 inventory/ledger 将步骤 1–7 划成互不重叠的 obligation/range context packs；每包绑定路径、哈希、capability/Skill receipts 后，并发调用同一个只读 `analysis-worker`：

- `context-pack(<对象>, 主干追踪)`　　　∥ 主干追踪
- `context-pack(<对象>, 分支枚举)`　　　∥ 分支枚举
- `context-pack(<对象>, 状态机提取)`　　∥ 状态机提取
- `context-pack(<对象>, 资源生命周期)`　∥ 资源生命周期
- `context-pack(<对象>, 异常传播)`　　　∥ 异常传播
- `context-pack(<对象>, 风险扫描, 透镜=<X>)` × 种子透镜数　∥ 风险扫描

**工件落盘（运行时职责）**：analysis-worker 只返回 strict `analysis_fragment`，不得写盘；运行时验证每个 obligation disposition、range 与 receipt，创建 `pangea-data/runs/<任务id>/`、更新 manifest，并持久化通过校验的 fragment 与模型贡献；primary 只消费固定工件。
**断点恢复**：启动前先读 `pangea-data/runs/<任务id>/manifest.md`——`complete` 跳过、`partial` 按 `progress.resume_hint` 续挖（协议见 architecture §6.2）。目录已存在时先问用户"续跑还是重挖"。
**并发降级**：analysis-worker 并发上限/返回体量待实测（T-3），超限则分批串行，语义不变。

## 5. SFMEA 环节（步骤 7，全透镜浅扫）

按 R-6.2 透镜双消费的"全透镜浅扫"模式：

1. **逐个种子透镜过一遍**（M1 种子：`资源泄漏`、`并发`、`超时恢复`，实际文件在 `core/lenses/可靠性/` 下，运行时按裸名解析后写入 context pack）——每个透镜建立可审计 `风险扫描` obligation，以“代码特征模式”栏为扫描指令。
2. **有命中** → 命中点入 SFMEA（`core/templates/SFMEA.md` 每行：失效模式/机理(引透镜)/代码证据(文件:行号)/影响/严重度·发生度·探测度/外部可观测表现/建议测试手段）。
3. **无命中** → 记一句话"免疫说明"（证据包 `immunity_note`），保证浅扫广度可审计。
4. **用例推导**：对 SFMEA 高危项与状态/边界，用 `core/methods/` 种子方法论推导——`状态转换`（对步骤 4 状态机）、`边界值分析`（对步骤 5/8 的规格边界）；方法选择走 `core/methods/_selector.md`。M1 种子两法之外的方法论 M3 补。

## 6. 收尾门

1. **汇总**：primary 收齐全部 `code_evidence` → 汇总为 SFMEA + 场景 + 黑盒用例（`methods/` 推导、`lenses/` 定风险优先级，两库正交组合 R-6.1）。
2. **auditor 复核**：Task 派 `auditor`（独立上下文，只审不改）→ `audit_opinion`（四组 checks：溯源/黑盒可执行性/覆盖/格式，见 §4.3）。
3. **覆盖审计 PASS** 才算完成；FAIL/CONCERNS → 按 `required_actions` 结构化回挖对应剧本（manifest `audit.rounds` +1）。**回挖 ≤ 2 轮**，仍不过则带 CONCERNS 出报告、首页标未决项，交用户裁决。
4. **产出**：报告落 `core/templates/报告-模块全量分析.md` 章节骨架（分析对象 → 主干/分支 → 状态/资源 → 异常传播 → SFMEA → 黑盒场景 → 用例清单 → 覆盖审计结论 → **待用户确认**）。
5. **回填询问**：R-7.4"是否回填知识"（透镜"典型历史缺陷"栏 / `protocols/` / `modules/`）写入报告末尾**"待用户确认"节**，不在对话内提问（Task 子调用未必能多轮对话，T-6）。
