# 场景作业流程：用例评审

> 执行主体：primary（测试设计工作流） ｜ 模式：**速度型 / 深度型** ｜ 输入要求：用例集（架构 §2.1 能力菜单）
> 上游：[architecture.md](../../docs/architecture.md) §2.1（场景衔接）｜ [requirements.md](../../docs/requirements.md) R-7.2（黑盒可执行性）、R-7.3（模板格式）、R-6.1
> **核心准绳**：评审是 primary 测试设计阶段"黑盒可执行 + 方法论完备"准绳落地最直接的场景——逐条用**外部触发/外部观测**这把尺子量已有用例，禁内部变量的步骤/判据一律判问题。

---

## 1. 场景定位

评审一份已有黑盒用例集：逐条按检查表判 **通过 / 问题 / 建议**，聚焦"这条用例黑盒真能执行吗、格式合规吗、方法论覆盖到位吗、能溯源吗"。是用例质量门，输出评审意见清单。

## 2. 输入（前置到 primary 收集）

- **用例集**：一批用例（文件路径或粘贴）。若声明了所用方法论/覆盖目标则一并收，供覆盖准则核对。
- **模式**：**速度型**（单条/少量用例，内联逐条评审）或**深度型**（整套用例集，需 auditor 独立复核）；判据见 `core/shared/调度规则.md` 二，不明确则问用户。
- **任务 id**（仅深度型）：`用例评审-<对象slug>-<日期>`。

## 3. 流程 / 编排

> 检查表 = 四道闸门，逐条用例过一遍，每道给结论。

1. **R-7.2 黑盒可执行性（首要闸门）**：两栏都要外部：
   - `外部触发手段` 是否只用协议报文构造 / CLI / 故障注入 / 压力 / 配置变更（非"调用内部函数""设置内部变量"）；
   - `观测判据(PASS/FAIL)` 是否只依据外部现象（协议报文/CLI 回显/告警/日志/性能统计/错误码）。
   凡出现 ❌"检查内部状态机变量""`refcnt==0`"一律判**问题**，并给出改成外部观测面的**建议**。
2. **R-7.3 模板格式符合**：对照 `core/templates/黑盒用例.md` 字段清单——用例编号（全局唯一，是 auditor case_id 锚点）/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论 字段是否齐全、`用例编号` 是否唯一可引。缺字段判**问题**。注意 R-7.3：不擅改用户已有格式，只指出缺漏，不重排版式。
3. **所选方法论覆盖准则**：按该用例 `推导方法论` 字段回到对应方法文件核覆盖——`状态转换` 核是否达"单迁移覆盖"基线、非法迁移是否出负向例；`边界值分析` 核每边界 min/max 两侧是否齐全（走 `core/methods/_selector.md` 确认选法本身是否对路）。方法与测试点不匹配、或覆盖有缺口，判**问题/建议**。
4. **溯源**：核 `覆盖目标`/`关联风险` 能否回指到迁移表 / 边界清单 / 透镜或 SFMEA 条目编号；事实性描述有无锚点（R-7.1）。`推导方法论` 字段应为裸方法名（不写路径），便于评审追溯完备性来源。断链判**建议**补溯源。
5. **逐条给结论**：每条用例输出三态之一——
   - **通过**：四道闸门全过；
   - **问题**：引具体字段 + 违规点（如"观测判据依赖内部变量，违 R-7.2"）；
   - **建议**：可执行的修正方向。
   汇成评审意见清单。

> 两库正交视角（R-6.1）：评审同时看"透镜风险有没有对准"（`lenses/`）与"方法论有没有推完备"（`methods/`）——用例只对了风险没推完备、或推完备却没对准风险，都记建议。

## 4. 双模式差异

| 环节 | 速度型 | 深度型 |
|---|---|---|
| 范围 | 单条 / 少量用例 | 整套用例集 |
| 落盘 | 不落 `pangea-data/runs/` | 建 `pangea-data/runs/<任务id>/` 存评审工件 |
| auditor | 不过 | 可选调 auditor 独立复核 |
| 产出 | 内联评审意见清单 | 完整评审报告 |

## 5. 收尾门

- **速度型**：内联产出评审意见清单，不落 `pangea-data/runs/`、不过 auditor。
- **深度型**：
  1. **可选调 auditor 做独立复核**：Task 派 `auditor`（独立上下文，只审不改）对整套用例集出 `audit_opinion`（溯源/黑盒可执行性/覆盖/格式四组 checks），与primary 逐条结论交叉，分歧项以 auditor 独立意见为准复核。
  2. **PASS/问题清零才算通过门**；仍有未决判问题 → 带 CONCERNS 出评审报告、标未决项。
  3. **产出**：用例评审报告——用例集概览 → 逐条评审（通过/问题/建议 + 引用字段锚点）→ 系统性问题归纳（如整套普遍缺外部观测判据）→ **待用户确认**。
  4. **回填询问**：R-7.4 写入报告末尾**"待用户确认"节**（T-6）。
