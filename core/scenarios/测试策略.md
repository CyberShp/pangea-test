# 场景作业流程：测试策略

> 归属族：test-designer ｜ 模式：**深度型** ｜ 输入要求：模块范围（架构 §2.1 能力菜单）
> 上游：[architecture.md](../../docs/architecture.md) §2.1（场景衔接）、§6（fan-out）｜ [requirements.md](../../docs/requirements.md) R-6.1（两库正交）、R-6.2、R-7.2
> **核心准绳**：策略里每一层的"测什么、怎么验"都必须收敛到**外部触发 + 外部观测**；两库正交（R-6.1）是本场景的组织主轴——`lenses/` 定风险优先级，`methods/` 定推导方法，二者组合成策略矩阵。

---

## 1. 场景定位

给定一个模块范围，制定分层黑盒测试策略：先扫风险定优先级，再选方法定推导路径，产出**分层测试策略 + 覆盖目标 + 资源估算框架**。回答"这个模块该投多少测试火力、按什么层次铺开、每层用什么方法把用例推完备"，是 `模块全量分析`（全量推导）之前的火力部署图。

## 2. 输入（前置到 Dispatcher 收集）

- **模块范围**：模块/特性边界 + （可选）源码路径。
  - 有 `可测试性分析` 报告则先读——盲区决定哪些面暂不投测试火力；
  - 无则本场景仍可基于范围与透镜浅扫定策略，盲区风险在报告中标注待补。
- **模式**：固定深度型。
- **任务 id**：`测试策略-<对象slug>-<日期>`（规则见 `core/shared/调度规则.md` 三）。

## 3. 流程 / 编排

1. **全透镜浅扫定风险优先级（lenses/ 侧）**：按 R-6.2 透镜双消费的"全透镜浅扫"模式，对模块范围逐个种子透镜过一遍——M1 种子 `资源泄漏`/`并发`/`超时恢复`（`core/lenses/_index.md`）：
   - 消费入口 `code-excavator(对象, 风险扫描, 透镜=<透镜名>)`，以透镜"代码特征模式"栏为扫描指令；
   - 命中点带 `文件:行号` 记为高风险面，无命中记一句话免疫说明（保浅扫广度可审计）；
   - 用透镜的 S·O·D 直觉给各面排优先级；
   - 证据包落盘职责在族 agent（excavator 只读），断点恢复读 manifest（architecture §6.2）。
2. **_selector 定推导方法（methods/ 侧）**：对每个风险面/规格面，走 `core/methods/_selector.md` 按"测试点特征→推荐方法"选法——有状态机/生命周期→`状态转换`；有数值规格/容量/序号/上限→`边界值分析`；一个面命中多行则多法并用、用例集合并去重。选到 M3 占位方法时回退最近种子方法并标"方法论待补（M3）"。
3. **两库正交组合成策略矩阵（R-6.1）**：把第 1 步的风险优先级（找什么风险）× 第 2 步的推导方法（怎么推完备）交叉，每个"高危面 × 适用方法"是一格策略单元：
   - 示例格 A——连接状态机：透镜层 `超时恢复` 定高优先级 → 方法层 `状态转换` 推迁移覆盖用例；
   - 示例格 B——最大连接数：透镜层 `资源泄漏` 定优先级 → 方法层 `边界值分析` 推 max/max+1 用例；
   - 正交矩阵保证既对准了风险、又推得出完备用例，并暴露"选了风险却没配推导方法"的空格。
4. **分层测试策略**：按测试深度分层铺开，每层界定范围/入口/退出准则，且每层的验证判据都外部可观测：
   - **冒烟**：核心通路能否建链 / 收发 / 拆链，快速判构建可测；退出准则=核心通路全绿。
   - **功能**：主干 + 分支的规格符合性（`边界值分析` 打规格边界，`状态转换` 打合法/非法迁移）；退出准则=分支与迁移全覆盖。
   - **可靠性**：透镜高危面（资源泄漏 / 并发 / 超时恢复）的长稳与异常路径；退出准则=高危 SFMEA 项均有对应用例。
   - **性能**：吞吐 / 时延 / 资源占用的外部性能统计（性能维度透镜 M3 补）；退出准则=各指标达规格阈值。
   - **异常**：故障注入 / 越界输入 / 静默断链下的健壮性与可观测反馈；退出准则=异常路径均有外部可观测判据。
5. **覆盖目标与资源估算框架**：
   - **覆盖目标**：每层给可核对的覆盖准则（`状态转换` 取"单迁移覆盖"基线、`边界值分析` 取每边界 min/max 两侧齐全），供后续 auditor `coverage` 核对；
   - **资源估算框架**：给三维框架而非锁死数字——用例规模量级 × 环境依赖（组网 / 压测工具 / 故障注入手段） × 人力时窗；
   - 估算细化随团队历史数据回填，本场景只搭框架维度。

> 分层里禁止出现黑盒够不着的层次或判据：凡某层验证只能靠内部变量，说明该层其实测不动，应回退 `可测试性分析` 补观测点或在策略里标为盲区不投火力（R-7.2）。

## 4. 收尾门

1. **auditor 复核**：Task 派 `auditor` → `audit_opinion`（溯源/黑盒可执行性/覆盖/格式四组 checks）。重点核：透镜浅扫是否全覆盖（命中或免疫说明，不漏项）、每层判据是否外部可观测、正交矩阵有无"选了风险却没配推导方法"的空格。
2. **PASS 才完成**；FAIL/CONCERNS → 按 `required_actions` 回挖（≤ 2 轮），超轮带 CONCERNS 出报告、标未决项，交用户裁决。
3. **产出**：测试策略报告——模块范围 → 风险优先级（全透镜浅扫结果 + 免疫说明）→ 正交策略矩阵（风险面 × 推导方法）→ 分层策略（冒烟/功能/可靠性/性能/异常）→ 覆盖目标与资源估算框架 → **待用户确认**。
4. **回填询问**：R-7.4"是否回填知识"（策略中新识别的风险面可回填透镜"典型历史缺陷"栏）写入报告末尾**"待用户确认"节**（T-6，不在对话内提问）。

## 5. 场景衔接（供 Dispatcher 推荐）

完成后推荐下一步（architecture §2.1 衔接表）：**模块全量分析**（按策略对各层做全量推导落到用例集）。
