# 初始化卸载时序（P10）

> 本剧本挖"建起来又拆掉的对称性"：追出模块/设备/连接的初始化(probe/建链)与卸载(remove/断链)全序列，比对两序列是否对称，找中途失败的回滚遗漏——存储底软 probe/remove、建链/断链是缺陷高发区。

## 目标

给定挖掘对象（模块/设备/连接/控制器），产出：
- **初始化序列**（资源按什么顺序申请/就绪）；
- **卸载序列**（资源按什么顺序拆除/释放）；
- **不对称项**（init 了却在 teardown 找不到对应 deinit 的资源，反之亦然）；
- **回滚缺口**（init 中途失败时，已就绪资源是否被完整回退）。

不做泛资源配对（那是 `资源生命周期`）；本剧本聚焦"时序对称性"——顺序依赖与拆除遗漏。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **追初始化序列**：定位 init 入口（`module_init`/`.probe`/`nvmet_*_add`/建链 `nvmet_tcp_alloc_queue`），按代码顺序列出资源就绪步骤（分配结构、建 socket、注册回调、起工作队列、置状态 live）。逐步记 `init_sequence[]`（步骤 + `位置` + 就绪的资源）。
2. **追卸载序列**：定位 exit 入口（`module_exit`/`.remove`/`nvmet_*_del`/断链 `nvmet_tcp_release_queue`），按代码顺序列出拆除步骤，记 `teardown_sequence[]`。
3. **比对对称性**：把 init 的每个"就绪项"与 teardown 的"拆除项"配对。找出——init 了但 teardown 无对应项、或拆除顺序与依赖不符（如先释放被依赖资源）——入 `asymmetries[]`，标 `位置`。
4. **查回滚完整性**：追 init 中途失败路径（`goto err_*` 阶梯），检查每个失败点是否只回退"已就绪"的资源、不多不少。回退遗漏/过度回退标【推测】入 `rollback_gaps[]` 并镜像到 `inferences[]` 给黑盒验证方法。

## 证据包字段

（字段名对齐 architecture §3 P10："init_sequence[] / teardown_sequence[] / asymmetries[] / rollback_gaps[]【推测】"）

```yaml
findings:
  init_sequence:                 # 初始化/建链有序步骤
    - 步骤: <序号或阶段名>
      动作: <就绪了什么资源，如 分配 queue 结构、建 socket、起 io_work>
      位置: <文件:行号>
  teardown_sequence:             # 卸载/断链有序步骤
    - 步骤: <序号或阶段名>
      动作: <拆除了什么资源>
      位置: <文件:行号>
  asymmetries:                   # 不对称项
    - 项: <哪个资源不对称>
      init位置: <文件:行号>
      teardown位置: <文件:行号 | 缺失>
      问题: <init 有 teardown 无 | 拆除顺序违反依赖>
  rollback_gaps:                 # 中途失败回滚缺口（全部【推测】，镜像 inferences[]）
    - 失败点: <文件:行号>
      现象: <已就绪的某资源在此失败分支未回退>
```

> 溯源纪律：`init_sequence/teardown_sequence/asymmetries` 为可定位事实，每条带 `位置: 文件:行号`；`rollback_gaps` 属推断，逐条镜像到 `inferences[]` 标【推测】并给黑盒验证方法。

## 存储领域示例

> **说明：本节行号为示意虚构，非真实代码锚点，仅示范字段填法。**

对象 `nvmet_tcp_alloc_queue` / `nvmet_tcp_release_queue`（NVMe/TCP 建链与断链时序）：

```yaml
findings:
  init_sequence:
    - { 步骤: 1, 动作: 分配 queue 结构 kzalloc, 位置: drivers/nvme/target/tcp.c:1700 }
    - { 步骤: 2, 动作: 初始化 crypto(Digest) 上下文, 位置: drivers/nvme/target/tcp.c:1715 }
    - { 步骤: 3, 动作: 注册 sk_data_ready/write_space 回调, 位置: drivers/nvme/target/tcp.c:1730 }
    - { 步骤: 4, 动作: INIT_WORK(io_work) 并 queue_work 置队列 live, 位置: drivers/nvme/target/tcp.c:1748 }
  teardown_sequence:
    - { 步骤: 1, 动作: 恢复 sk 原回调、cancel io_work, 位置: drivers/nvme/target/tcp.c:1790 }
    - { 步骤: 2, 动作: 释放 crypto 上下文, 位置: drivers/nvme/target/tcp.c:1808 }
    - { 步骤: 3, 动作: 释放 queue 结构, 位置: drivers/nvme/target/tcp.c:1820 }
  asymmetries:
    - 项: sk 回调注册
      init位置: drivers/nvme/target/tcp.c:1730
      teardown位置: drivers/nvme/target/tcp.c:1790
      问题: 对称（示例中此项 OK，列出以示配对）
  rollback_gaps:
    - 失败点: drivers/nvme/target/tcp.c:1740
      现象: 步骤3 注册回调后、步骤4 前若失败，goto err 未恢复 sk 原回调即释放 queue
inferences:
  - claim: 【推测】建链中途(回调已注册、io_work 未起)失败时未反注册 sk 回调即释放 queue，遗留悬空回调
    basis: :1740 失败分支 goto err_free 直接释放，未见对应 restore_sk_callbacks
    verify_method: 构造建链中途失败（如注入 crypto 分配失败/内存压力），反复触发后观测是否偶发 use-after-free 崩溃或 sk 回调空指针告警
```

## 与黑盒观测的接触面

时序对称性是内部结构事实，黑盒看不到 init/teardown 步骤；本剧本的价值在把"拆除遗漏/回滚缺口"转成可压测的黑盒场景：
- `asymmetries` 中"init 有 teardown 无"的项是**资源累积泄漏**的黑盒假设——primary 据此设计"反复建链/断链循环压测 + 观测资源单调上涨"用例；
- `rollback_gaps` 的每个失败点经 `verify_method` 转成"注入中途失败（内存压力/参数非法）→ 反复触发 → 观测崩溃或告警"的黑盒故障注入用例；
- 卸载顺序违反依赖的项提示"卸载竞态"（拆除中仍有报文进来），primary 据此构造"断链瞬间并发下发 IO"的时序用例；本剧本只交时序事实，泄漏/竞态是否成灾交黑盒压测证实。
