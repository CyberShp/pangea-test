# 状态机提取（P3）

> 本剧本挖"是什么"：提取对象的状态集合、状态迁移和触发事件——它有哪些状态、从哪个态因什么事件跳到哪个态、跳的时候做了什么、非法迁移怎么处理，以及外部用什么手段能驱动/观测这些状态。

## 目标

给定挖掘对象（连接 / 会话 / 控制器 / 队列等有状态实体），产出一张完整状态机：状态清单、迁移表（源态→事件→目标态+动作）、非法迁移处置，以及**状态↔外部手段/观测**的映射。存储底软状态机密集（TCP 连接态、iSCSI 会话态、NVMe 控制器态、队列态），是黑盒场景设计的富矿。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **找状态变量**：grep 状态枚举/字段。特征：`enum *_state`、`->state =`、`atomic_set(&x->state, ...)`、`NVMET_TCP_Q_*`、`ISCSI_STATE_*`、状态机 `switch (x->state)`。
2. **列全状态**：从枚举定义与所有赋值点收全状态集合，入 `states[]`（每态附首次定义/典型赋值 `位置`）。
3. **列迁移**：grep 所有 `->state = <新态>` 赋值点，回溯每处的前置条件（源态 + 触发事件）与随迁移执行的动作，形成 `transitions[]`（from / event / to / action / 位置）。
4. **标非法迁移**：找对非预期事件/非法态转移的处理（`WARN`、拒绝、断连、`default` 分支），入 `illegal_transition_handling[]`。
5. **映外部手段与观测**：为每个迁移/状态标注：用什么**外部手段**能驱动它（建链/断链报文、CLI 命令、故障注入），以及该态在外部**如何观测**（CLI 查会话态、能否收发 IO、告警）。入 `external_trigger_map[]`。

## 证据包字段

```yaml
findings:
  states:                      # 状态集合
    - { 状态: <状态名/枚举值>, 位置: <文件:行号> }
  transitions:                 # 迁移
    - from: <源态>
      event: <触发事件>
      to: <目标态>
      action: <迁移时执行的动作>
      位置: <文件:行号（赋值点）>
  illegal_transition_handling: # 非法迁移处置
    - { 场景: <非法迁移描述>, 处理: <如何处理>, 位置: <文件:行号> }
  external_trigger_map:        # 状态 ↔ 外部手段/观测
    - 迁移或状态: <关联的 transition/state>
      外部触发手段: <建链报文 | 断链 | CLI | 故障注入 …>
      外部观测: <CLI 查连接态 | 能否收发IO | 告警 | 抓包>
```

> 溯源纪律：`states`/`transitions` 为事实必带行号；"某外部手段能驱动某迁移"若无直接代码证据，标【推测】入 `inferences[]` 并给黑盒验证方法。

## 存储领域示例

对象 `nvmet_tcp_queue`（NVMe/TCP target 连接队列状态机）：

```yaml
states:
  - { 状态: NVMET_TCP_Q_CONNECTING, 位置: drivers/nvme/target/tcp.c:120 }
  - { 状态: NVMET_TCP_Q_LIVE,       位置: drivers/nvme/target/tcp.c:121 }
  - { 状态: NVMET_TCP_Q_DISCONNECTING, 位置: drivers/nvme/target/tcp.c:122 }
transitions:
  - from: NVMET_TCP_Q_CONNECTING
    event: 收到合法 ICReq 并回 ICResp 完成初始化连接
    to: NVMET_TCP_Q_LIVE
    action: 置 queue->state=LIVE，允许业务 IO
    位置: drivers/nvme/target/tcp.c:1560
illegal_transition_handling:
  - { 场景: LIVE 前收到非 ICReq 的业务 PDU, 处理: 发 C2HTermReq 并转 DISCONNECTING, 位置: drivers/nvme/target/tcp.c:1122 }
external_trigger_map:
  - 迁移或状态: CONNECTING→LIVE
    外部触发手段: 主机发起 NVMe/TCP 建链（TCP 三次握手 + ICReq）
    外部观测: target CLI 查询该连接状态为 live；主机侧可正常下发 IO
```

## 与黑盒观测的接触面

铁律禁止黑盒直接读内部状态变量（`sk_state`、`queue->state` 都看不到）。本剧本的 `external_trigger_map` 正是这条禁令的解药：
- 把"内部状态"翻译成"外部可观测代理"——用能否收发 IO、CLI 会话态回显、抓包握手完成等替代直接读变量；
- `transitions` 表天然映射为 `core/methods/状态转换.md` 的状态迁移测试输入：每条迁移 = 一条"施加事件→断言目标态可观测代理"的用例；
- `illegal_transition_handling` 是健壮性/异常用例的金矿（在错误态施加事件，观测是否按预期拒绝/断连）；
- 供族 agent 与 auditor 做"状态覆盖"审计（是否每个状态与关键迁移都有对应黑盒场景）。
