# 异常传播（P5）

> 本剧本挖"是什么"：追踪错误码/异常从产生到最终处置的整条传播链——错误在哪冒出来、沿调用栈怎么层层往上传（原样返回？转译成别的码？被吞掉？）、最终怎么处置（重试/回滚/上报/静默），以及外部能不能看见这个错。

## 目标

给定挖掘对象，追出其内部错误的完整传播路径：错误产生点 → 中间每一跳的处理（透传/转译/吞掉）→ 最终 sink（处置方式），并标出**外部可观测的错误表现**。存储链路长、错误码转译多（block 层 errno ↔ NVMe status ↔ SCSI sense ↔ 协议 TermReq），被吞掉的错误是 FST 逃逸重灾区。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **找错误产生点**：grep 错误源头：
   - 返回码：`return -EIO`/`-ENOMEM`/`-ETIMEDOUT`；`ERR_PTR`/`IS_ERR`；
   - errno / NVMe status：`NVME_SC_*`；SCSI sense 构造；
   - 校验失败点（CRC、CmdSN、长度、能力）产生的错误。
   逐个入 `error_origins[]`（错误 + 位置 + 触发条件）。
2. **追传播**：从每个产生点沿调用返回方向追，每跳判定处理方式：
   - **透传**：原样 `return ret` 上抛；
   - **转译**：换成另一种错误表示（errno→NVMe status、内部码→协议 TermReq FES）；
   - **吞掉**：`ret` 被忽略/仅打日志不上报/`goto out` 后返回 0。
   形成 `propagation_chains[]`（origin→…→sink，每跳位置 + 是否转译/吞掉）。
3. **定 sink**：找最终处置——重试、回滚、上报上层、复位连接、静默丢弃。标在链尾。
4. **标外部错误面**：该错误最终有无外部可观测表现（错误码回主机、告警、日志、连接复位、IO 失败），入 `observable_error_surface[]`；**被吞掉且无外部表现的**要显式标出（黑盒盲区 + 潜在逃逸点）。

## 证据包字段

```yaml
findings:
  error_origins:               # 错误产生点
    - { 错误: <错误码/异常，如 -ETIMEDOUT>, 位置: <文件:行号>, 触发条件: <何时产生> }
  propagation_chains:          # 传播链
    - origin: <起点错误 + 位置>
      hops:                    # 每一跳
        - { 位置: <文件:行号>, 处理: <透传 | 转译为X | 吞掉> }
      sink: <最终处置：重试 | 回滚 | 上报 | 复位连接 | 静默丢弃>
      sink位置: <文件:行号>
  observable_error_surface:    # 外部可观测的错误表现
    - { 表现: <错误码回主机 | 告警 | 日志 | 连接复位 | IO失败>, 位置: <文件:行号> | 无（黑盒盲区）}
```

> 溯源纪律：每跳/sink 必带行号；"某错误被静默吞掉导致外部无感"若靠推断，标【推测】入 `inferences[]` 并给验证方法。

## 存储领域示例

对象 `nvmet_tcp_try_recv`（收包路径的错误传播）：

```yaml
error_origins:
  - { 错误: -EAGAIN/负错误码, 位置: drivers/nvme/target/tcp.c:1305, 触发条件: recvmsg 返回错误或数据不足 }
propagation_chains:
  - origin: "-EIO from kernel_recvmsg @ tcp.c:1305"
    hops:
      - { 位置: drivers/nvme/target/tcp.c:1310, 处理: 透传（return ret 上抛至 io_work）}
      - { 位置: drivers/nvme/target/tcp.c:1230, 处理: 转译为 触发连接释放 nvmet_tcp_schedule_release_queue }
    sink: 复位连接（关闭 socket，队列转 DISCONNECTING）
    sink位置: drivers/nvme/target/tcp.c:1240
observable_error_surface:
  - { 表现: 连接复位（主机侧感知 TCP 断开 + IO 超时失败）, 位置: drivers/nvme/target/tcp.c:1240 }
```

## 与黑盒观测的接触面

异常传播链的终点决定了"这个错黑盒看不看得见"，这正是可测试性的关键判据：
- **有外部错误面的链** → 直接推导异常/负向用例：外部制造错误产生条件（构造非法报文、注入网络故障、超时），断言 `observable_error_surface`（主机收到特定 NVMe status、连接复位、告警）；
- **被吞掉且无外部表现的链** → 高价值发现：既是黑盒盲区，也常是缺陷逃逸点，族 agent 需借旁路观测或标"不可黑盒验证"，并回填透镜"典型历史缺陷"；
- **转译点**是用例断言的精度来源——告诉族 agent 主机侧最终看到的是哪种错误码，避免断言错层级；
- 供 troubleshooter（M2）反向使用：从日志/报文里的错误表现，顺 `propagation_chains` 逆推内部根因候选。
