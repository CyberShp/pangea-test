# 配置规格盘点（P11）

> 本剧本挖"能调什么、上限多少、超了会怎样"：盘点对象的可配置项（含默认值与配置手段）、规格上限（队列深度/连接数/超时/批量上限）及其校验点，标出超限行为与未校验的外部输入——为黑盒的边界值与配置组合用例供弹药。

## 目标

给定挖掘对象，产出：
- 所有**可配置项**（项名、默认值、配置来源、读取位置）；
- 所有**规格上限/规格常量**（上限值、校验位置、超限行为）；
- **未校验的外部输入**（协议协商值/配置值未做上限校验即使用的点）。

不做风险机理判定（交 `风险扫描` 透镜=规格）；本剧本只做客观清点，把散落的常量与配置读取收成规格表。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **找配置读取点与默认值**：grep 配置读取特征：`module_param`/`MODULE_PARM_DESC`、configfs `store`/`show` 回调、sysfs 属性、设备树/`of_property_read_*`。记项名、默认值、来源、`位置` 入 `config_items[]`。
2. **找规格常量与上限校验**：grep 规格上限特征：`#define ... MAX/DEPTH/LIMIT`、`NVMET_*`、队列深度 `sqsize`/`queue_size`、连接数上限、批量上限、`if (x > MAX) ...` 校验分支。记 `spec_limits[]`（上限值 + 校验位置 + 超限行为）。规格常量成对写"数值+名称"。
3. **标超限行为**：对每个规格上限，判定超限时的处置——**拒绝**（返回错误/拒绝连接）/ **截断**（clamp 到上限）/ **未校验**（直接使用外部值）。填入 `spec_limits[].超限行为`。
4. **标未校验输入**：找外部可控输入（协议协商字段如 NVMe `sqsize`/iSCSI `MaxRecvDataSegmentLength`、配置值）在使用前**无上限校验**的点，入 `unvalidated_inputs[]`，标【推测】并镜像到 `inferences[]` 给黑盒验证方法。

## 证据包字段

（字段名对齐 architecture §3 P11："config_items[]{项,默认值,来源,位置} / spec_limits[]{上限,校验位置,超限行为} / unvalidated_inputs[]【推测】"）

```yaml
findings:
  config_items:                  # 可配置项
    - 项: <配置项名，如 nvmet_tcp io_work 轮询预算>
      默认值: <默认值，带宏名>
      来源: <module_param | configfs | sysfs | 协议协商>
      位置: <文件:行号>
  spec_limits:                   # 规格上限/规格常量
    - 上限: <上限值+名称，如 NVMET_QUEUE_SIZE=1024 队列深度上限>
      校验位置: <文件:行号 | 无校验>
      超限行为: <拒绝 | 截断(clamp) | 未校验直接使用>
  unvalidated_inputs:            # 未校验外部输入（全部【推测】，镜像 inferences[]）
    - 输入: <外部可控输入，如 Connect 命令携带的 sqsize>
      使用位置: <文件:行号>
      风险: <无上限校验即用于分配/索引>
```

> 溯源纪律：`config_items/spec_limits` 为可定位事实，每条带 `位置: 文件:行号`。规格常量成对写"数值+名称"（如 `NVMET_QUEUE_SIZE=1024 队列深度上限`）。`unvalidated_inputs` 属推断，逐条镜像到 `inferences[]` 标【推测】并给黑盒验证方法。

## 存储领域示例

> **说明：本节行号为示意虚构，非真实代码锚点，仅示范字段填法。**

对象 `nvmet_tcp` 队列/连接规格：

```yaml
findings:
  config_items:
    - 项: nvmet_tcp target 监听端口
      默认值: 4420（NVME_TCP_DISC_PORT）
      来源: configfs port addr_trsvcid 属性
      位置: drivers/nvme/target/configfs.c:220
  spec_limits:
    - 上限: NVMET_QUEUE_SIZE=1024 每队列命令深度上限
      校验位置: drivers/nvme/target/core.c:1360
      超限行为: 拒绝（Connect 时 sqsize 超限返回 Invalid Queue Size 状态码 5h）
    - 上限: NVMET_TCP_RECV_BUDGET=8 单次收包预算轮次
      校验位置: 无校验（内部固定常量，非外部可控）
      超限行为: 未校验直接使用（内部调度参数，无外部输入面）
  unvalidated_inputs:
    - 输入: Connect 命令携带的 sqsize（主机声明队列深度）
      使用位置: drivers/nvme/target/tcp.c:1005
      风险: 若校验分支被绕过，超大 sqsize 可能用于队列内存分配导致过量申请
inferences:
  - claim: 【推测】sqsize 上限校验仅在 core.c:1360，若 tcp 侧另有路径先用该值分配则存在校验旁路
    basis: :1005 读取 sqsize 与 :1360 校验分处两文件，需确认调用先后
    verify_method: 构造 Connect 命令携带超大/边界 sqsize（1024、1025、0xFFFF），观测 target 是否按规格返回 Invalid Queue Size(5h) 拒绝、还是异常分配/崩溃
```

## 与黑盒观测的接触面

规格上限与配置项深埋代码，黑盒同学最需要的正是这张"能调什么、边界在哪"的表：
- `spec_limits` 的每个上限直接是**边界值用例**（`methods/边界值分析`）的输入——primary 据上限值构造 上限-1/上限/上限+1 三点，用 `超限行为` 作为观测判据（该拒绝的是否拒绝、该截断的是否截断）；
- `config_items` 的 `来源` 告诉黑盒"用什么外部手段改这个配置"（configfs 写、协议协商），是配置组合用例的前置操作；
- `unvalidated_inputs` 是**畸形/超限输入用例**的靶点，经 `verify_method` 转成"下发超规格协商值观测是否被拒或崩溃"的黑盒动作；本剧本只交规格事实，超限是否成灾交 `风险扫描` 透镜=规格 判机理、交黑盒边界压测证实。
