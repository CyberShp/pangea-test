# 分支枚举（P2）

> 本剧本挖"是什么"：穷举对象内部所有条件分支及其进入条件——每个 if/switch/错误检查/能力协商岔路走向哪、什么条件才进得去、从外部能不能触发、进去后外部看得出差别吗。

## 目标

给定挖掘对象，产出一张"分支全表"：把对象内每一处控制流岔路都列出来，标注进入条件、分支去向、**外部可触发性**（黑盒能否制造该条件）与**可观测差异**（进不同分支外部现象是否不同）。为 primary 判定分支覆盖与黑盒可达性提供底账。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **遍历分支源**：grep/通读对象内所有控制流岔路，逐类扫：
   - 条件判断：`if` / `else if` / 三元 / `switch-case`；
   - 错误检查分支：`if (ret)` / `if (IS_ERR(...))` / `if (unlikely(...))` / `goto err_*`；
   - 能力/协商分支：标志位判断（`if (queue->hdr_digest)`、`ctrl->cap & ...`、`flags & NVME_TCP_F_*`）；
   - 边界/规格分支：长度校验、深度校验、越界检查（`if (len > max)`）。
2. **记录每分支**：对每处岔路记进入条件、分支去向（进入后调用什么/返回什么）、`位置: 文件:行号`。
3. **判外部可触发性**【推测标注】：判断黑盒同学能否从外部制造该条件（可构造报文字段？可配置？还是仅内部内存分配失败等难触发）。可触发性推断入 `inferences[]` 并给验证方法。
4. **判可观测差异**：进入该分支 vs 未进入，外部现象是否不同（回不同错误码 / 有无告警 / 报文差异 / 无任何外部差异）。无外部差异的分支要显式标出（这类是黑盒盲区，供 primary 关注）。

## 证据包字段

```yaml
findings:
  branches:
    - 条件: <进入该分支的条件，如 pdu->hdr.hlen 校验失败>
      位置: <文件:行号>
      分支去向: <进入后做什么，如 发送 C2HTermReq 并关连接>
      外部可触发性: <可构造报文触发 | 需配置触发 | 难以外部触发【推测】>
      可观测差异: <进入该分支外部能看到什么差异 | 无外部差异（黑盒盲区）>
```

> 溯源纪律：`条件`/`位置` 为事实必带行号；`外部可触发性` 属判断，标【推测】并在 `inferences[]` 给黑盒验证方法。

## 存储领域示例

对象 `nvmet_tcp_recv_pdu`（PDU 头校验分支）：

```yaml
branches:
  - 条件: pdu->hdr.type 非法（不在已知 opcode 集合）
    位置: drivers/nvme/target/tcp.c:1130
    分支去向: 走 default，发送 C2HTermReq(FES=Invalid PDU Header)，关闭连接
    外部可触发性: 可构造报文触发（发一个 type 字段非法的 PDU）
    可观测差异: 抓包可见 C2HTermReq 响应 + 连接被 target 主动 RST/FIN
  - 条件: hdr_digest 使能且 header CRC 校验失败
    位置: drivers/nvme/target/tcp.c:1165
    分支去向: 发送 C2HTermReq(FES=3h Header Digest Error)
    外部可触发性: 可构造报文触发（发 CRC 错误的 PDU 头）【推测：需先在建链时协商开启 hdr_digest】
    可观测差异: 抓包可见 C2HTermReq(FES=3h Header Digest Error) + 连接终止
inferences:
  - claim: 【推测】hdr_digest 分支需建链时 ICReq/ICResp 协商开启 HDGST 才可达
    basis: 该分支受 queue->hdr_digest 标志保护（tcp.c:1165），标志来源于建链协商
    verify_method: 建链时 ICReq 置 HDGST 标志开启摘要，再发头 CRC 错误的 PDU，抓包断言 C2HTermReq(FES=3h)；不开启协商时同报文应走非法 PDU 路径而非摘要错误路径
```

> 注：凡写 FES 一律"数值+名称"成对（如 `FES=3h Header Digest Error`），防止单边写错误值被抄进抓包断言。

## 与黑盒观测的接触面

分支表是"黑盒可测性画像"的原料：
- **可触发 × 可观测的分支** → 直接可推导为黑盒用例（构造触发条件 → 断言可观测差异），是 primary 的高价值素材；
- **可触发但无外部差异的分支** → 黑盒盲区，primary 需借旁路观测（日志 / 统计计数）或标为"不可黑盒验证"，回填透镜与覆盖审计；
- **难以外部触发的分支**（如 kmalloc 失败）→ 提示需故障注入手段，或判为超出黑盒范围；
- `外部可触发性` + `可观测差异` 两列直接喂给 auditor 的 `coverage`（分支覆盖维度）与 `blackbox_executability` 检查。
