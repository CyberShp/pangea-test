# 资源生命周期（P4）

> 本剧本挖"是什么"：配对对象里各类资源的申请与释放，找生命周期缺口——每个内存/连接/队列/引用计数/锁/fd 在哪申请、在哪释放、配没配上对，尤其异常路径上是否漏释放或双重释放。

## 目标

给定挖掘对象，逐一列出其管理的资源，把 alloc↔free、get↔put、lock↔unlock 成对配起来，标出**未配对**、**异常路径漏释放**、**双重释放**等缺口。存储底软长时运行、频繁建链断链，资源泄漏是 FST 逃逸高发区，本剧本产出直接喂"资源泄漏"透镜与稳定性用例。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **列资源**：grep 资源获取点，逐类扫：
   - 内存：`kmalloc`/`kzalloc`/`kmem_cache_alloc`/`__get_free_pages`/`sgl_alloc`；
   - 连接/socket：`sock_create`/`kernel_accept`；
   - 队列/描述符：`blk_mq_alloc_*`、命令/请求对象池取用；
   - 引用计数：`kref_get`/`refcount_inc`/`get_device`/`nvme_get_ctrl`；
   - 锁：`spin_lock`/`mutex_lock`/`down`；
   - fd/文件：`fget`/`filp_open`。
2. **配对**：对每个资源找其释放点，配 alloc↔free、get↔put、lock↔unlock，记双方 `位置`。
3. **查缺口**：重点看异常/错误出口（`goto err_*`、提前 `return ret`、断链回收路径）：
   - **漏释放**：正常路径释放了，某条 `goto` 跳过了释放；
   - **双重释放**：多条路径都释放同一资源，或释放后未置 NULL 又释放；
   - **未配对**：只见 alloc 不见 free（或反之）。
   缺口属推断的，标【推测】入 `inferences[]` 并给验证方法。

## 证据包字段

```yaml
findings:
  resources:
    - 资源: <资源名/类型，如 cmd->req.sg 散列表>
      alloc位置: <文件:行号>
      free位置: <文件:行号 | 无>
      配对状态: <已配对 | 未配对 | 疑似漏释放 | 疑似双重释放>
      异常路径缺口: <哪条异常路径可能漏/重释放，一句话【推测】| 无>
```

> 溯源纪律：`alloc位置`/`free位置` 必带行号；"某异常路径漏释放"是推断，须在 `inferences[]` 给出黑盒验证方法（通常是压测 + 外部资源监控）。

## 存储领域示例

对象 `nvmet_tcp_cmd`（NVMe/TCP 命令对象的散列表内存）：

```yaml
resources:
  - 资源: cmd->req.sg（命令散列表 scatterlist）
    alloc位置: drivers/nvme/target/tcp.c:870
    free位置: drivers/nvme/target/tcp.c:915
    配对状态: 疑似漏释放
    异常路径缺口: 连接复位时走 :902 goto out 直接回收 cmd，未见对 :870 分配的 sg 调 sgl_free【推测】
inferences:
  - claim: 【推测】异常断链路径 tcp.c:902 在连接复位时漏释放 cmd->req.sg
    basis: 正常路径 :915 有 sgl_free；:902 异常分支 goto out 未见释放调用
    verify_method: 反复建链/异常断链压测（如主机侧强制 RST），观测 target 侧内存单调上涨——查 /proc/slabinfo 对应 slab 或阵列内存告警
```

## 与黑盒观测的接触面

资源缺口本身是内部事实，但其外部表现是黑盒最擅长抓的"累积型现象"：
- 每个 `疑似漏释放`/`未配对` 缺口 → 一条稳定性/长稳用例：反复触发对应异常路径（建链断链循环、异常报文风暴），外部观测**内存/连接数/句柄数是否单调不回落**（`/proc/slabinfo`、阵列内存告警、连接计数 CLI）；
- `疑似双重释放` → 通常表现为 crash/oops 或数据踩踏，用例侧重"触发后系统是否异常复位"；
- 这类缺口的验证方法天然是黑盒可执行的（外部施压 + 外部资源监控），无需内部插桩，契合铁律二；
- 产出直接回填 `lenses/可靠性/资源泄漏.md` 的命中记录，并供 auditor 做资源维度覆盖审计。
