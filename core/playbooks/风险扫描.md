# 风险扫描（P0，通用流程）

> 本剧本挖"有什么风险"，而非"是什么"。它**不含固定的"找什么"**——扫描指令来自透镜文件。以某个 DFX 透镜为镜片，扫描对象内匹配该透镜"代码特征模式"的风险点，命中即记证据，未命中给免疫理由。

## 目标

给定挖掘对象 + 一个透镜名（裸名，如 `资源泄漏`），按步骤 1 的解析规则加载透镜文件，以其"**代码特征模式**"栏作为 grep/阅读指令扫描对象，逐一记录命中点（证据 + 匹配机理 + 可能失效模式），无命中时给出"免疫理由"（供族 agent 的全透镜浅扫模式一句话交代该维度已扫且干净）。

**与结构类剧本的根本区别**：结构类（主干追踪/分支枚举/…）自带固定挖掘步骤；本剧本步骤是"元流程"，具体扫什么由透镜注入，因此一个"风险扫描"剧本 × N 个透镜 = N 种风险扫描能力，无需为每个透镜写独立剧本。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **加载透镜**：透镜以**裸名**传入（如 `资源泄漏`），文件路径按以下顺序解析：① 查 `core/lenses/_index.md` 登记表取实际路径（透镜按 DFX 维度分目录存放，如 `core/lenses/可靠性/资源泄漏.md`）；② 未登记则 Glob `core/lenses/**/<透镜名>.md`；③ 仍找不到或文件无"代码特征模式"栏 → 写入 `open_questions[]` 并停在此步（partial）。取"**代码特征模式**"栏——这是本剧本唯一的"找什么"来源。
2. **按特征模式扫描**：把每条代码特征模式转成 grep 关键词/阅读指令，在对象内逐条扫。例如"资源泄漏"透镜的特征模式可能是"`goto err` 后是否跳过 free""alloc 无对应 free"等；"并发"透镜可能是"共享数据无锁访问""持锁调用可能睡眠的函数"。
3. **记录命中**：每个命中点记 `位置: 文件:行号`、命中的具体特征模式、该透镜给出的风险机理、可能导致的失效模式，入 `hits[]`。命中里的"会失效"属推断，标【推测】入 `inferences[]` 并给黑盒验证方法。
4. **无命中给免疫理由**：若对象未匹配该透镜任何特征模式，在 `immunity_note` 一句话说明为何该维度免疫（如"本对象不管理动态内存，无泄漏面"），供全透镜浅扫留痕。

## 证据包字段

```yaml
findings:
  lens: <透镜名>               # 必填，等于外层 lens 字段，如 资源泄漏
  hits:                        # 命中的风险点（无命中则为空）
    - 位置: <文件:行号>
      命中的特征模式: <匹配了透镜"代码特征模式"栏的哪一条>
      风险机理: <透镜给出的机理，为何这是风险>
      可能失效模式: <可能导致的外部失效，如 内存单调上涨最终 OOM>
  immunity_note: <无命中时的免疫理由；有命中则为 null 或省略>
```

> 外层字段：`playbook: 风险扫描`、`lens: <透镜名>` 必填（`lens` 仅风险扫描填）。
> 溯源纪律：`hits` 每条必带 `位置: 文件:行号`；"会引发某失效"是推断，标【推测】入 `inferences[]` 并给黑盒验证方法。

## 存储领域示例

调用 `code-excavator(连接状态机, 风险扫描, 透镜=资源泄漏)`：

```yaml
findings:
  lens: 资源泄漏
  hits:
    - 位置: drivers/nvme/target/tcp.c:902
      命中的特征模式: "异常出口 goto 跳过资源释放"（资源泄漏透镜特征模式）
      风险机理: 连接复位走 goto out，绕过正常路径 :915 的 sgl_free，散列表内存未回收
      可能失效模式: 反复异常断链累积泄漏，target 侧内存单调上涨，长稳后 OOM/内存告警
  immunity_note: null
inferences:
  - claim: 【推测】:902 异常路径漏释放 cmd->req.sg 导致内存泄漏
    basis: 正常路径 :915 有 sgl_free，异常分支 goto out 未见对应释放
    verify_method: 建链/异常断链循环压测，观测 /proc/slabinfo 对应 slab 或阵列内存告警是否单调上涨
```

（若换 `透镜=并发` 且对象无共享可变状态，则 `hits: []`、`immunity_note: "本对象为单执行流处理，无跨上下文共享可变数据，无数据竞争面"`。）

## 与黑盒观测的接触面

风险扫描产出的是"内部风险假设"，必须经本接触面才落到黑盒可验证：
- 每个 `hits` 条目的 `可能失效模式` 即黑盒**失效假设**，`inferences[].verify_method` 给出**外部验证路径**（施压手段 + 外部观测指标），族 agent 据此生成 SFMEA 行与验证用例；
- `immunity_note` 支撑"全透镜浅扫"的覆盖闭环——auditor 的 `coverage.dimension=全透镜浅扫` 检查每个透镜维度是否都有命中记录或免疫说明，无留痕即判 gap；
- 风险扫描不产出结论性测试建议（那是族 agent 职责），只交"风险事实 + 验证入口"；透镜的"代码特征模式"栏是本剧本与透镜库的唯一耦合面，透镜升级不改本剧本。
