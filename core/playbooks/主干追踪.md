# 主干追踪（P1）

> 本剧本挖"是什么"：找到对象的所有入口点，追出正常路径的主干调用链——这个对象从哪里被调起、正常跑一遍会经过哪些函数、在哪里冒出外部可观测的动静。

## 目标

给定一个挖掘对象（函数 / 模块 / 处理路径），产出：
- 它的全部入口点（谁、在什么条件下调起它）；
- 沿"正常/成功路径"追出的有序主干函数序列；
- 主干沿途与外部世界（报文 / CLI / 日志 / 告警）的接触面。

异常分支、错误处置不在本剧本范围（交 `分支枚举` / `异常传播`）；本剧本只画"一切正常时的主动脉"。

## 步骤

（步骤号与证据包 `progress.done_steps` 对应）

1. **定位入口**：grep 注册回调 / 系统调用 / 报文分发表 / CLI 命令表。存储底软常见入口特征：
   - `.recv = `、`.data_ready`、`ops` 结构体成员赋值（如 `nvmet_tcp_ops`）；
   - `module_init` / `.probe` / `register_*`；
   - PDU/命令分发表（`switch (pdu->hdr.type)`、`cmd->common.opcode` 跳转表）；
   - CLI/配置入口（configfs `store` 回调、`ioctl` 分发）。
   逐个记入 `entries[]`，标 `位置: 文件:行号` 与触发条件。
2. **追主干**：从每个入口沿正常返回值路径（`ret == 0` / 成功分支）跟进被调函数，形成有序 `main_chain[]`。跳过 `if (err) goto` 类异常出口，只走 happy path。每跳记函数名、`位置`、一句话作用。
3. **标锚点**：确认 `main_chain` 每一跳都带 `文件:行号`；追不动（函数指针无法静态确定目标）的跳转，写入 `inferences[]` 并给验证方法，不硬写成事实。
4. **标接触面**：沿主干找与外部可观测点耦合处——发包/回包、CLI 回显、`pr_info`/`dev_dbg` 日志、告警上报、统计计数器自增，记入 `observable_touchpoints[]`（类型 + 位置 + 外部现象）。

## 证据包字段

```yaml
findings:
  entries:                     # 入口点
    - symbol: <入口符号，如 nvmet_tcp_data_ready>
      位置: <文件:行号>
      触发条件: <被调起的条件，如 socket 收到数据 data_ready 回调>
  main_chain:                  # 正常路径有序调用链
    - 函数: <函数名>
      位置: <文件:行号>
      作用: <这一跳做什么>
  observable_touchpoints:      # 与外部可观测点的接触面
    - 类型: <报文 | CLI回显 | 日志 | 告警 | 统计计数>
      位置: <文件:行号>
      现象: <外部能看到什么，如 回 C2HData PDU>
```

> 溯源纪律：`findings` 每条必带 `位置: 文件:行号`；给不出行号的推断（如函数指针实际指向）移到 `inferences[]` 并附黑盒验证方法。

## 存储领域示例

对象 `nvmet_tcp_recv`（NVMe/TCP target 收包主干）：

```yaml
entries:
  - symbol: nvmet_tcp_data_ready
    位置: drivers/nvme/target/tcp.c:1642
    触发条件: 底层 socket 有数据到达触发 sk_data_ready 回调
main_chain:
  - { 函数: nvmet_tcp_io_work,    位置: drivers/nvme/target/tcp.c:1203, 作用: 工作队列处理入口 }
  - { 函数: nvmet_tcp_try_recv,   位置: drivers/nvme/target/tcp.c:1287, 作用: 循环收取 PDU }
  - { 函数: nvmet_tcp_recv_pdu,   位置: drivers/nvme/target/tcp.c:1108, 作用: 解析 PDU 头 }
  - { 函数: nvmet_tcp_handle_h2c_data_pdu, 位置: drivers/nvme/target/tcp.c:990, 作用: 处理 H2CData }
observable_touchpoints:
  - { 类型: 报文, 位置: drivers/nvme/target/tcp.c:1420, 现象: 构造并发送 R2T PDU 请求主机送数据 }
```

## 与黑盒观测的接触面

主干链本身是内部事实，黑盒同学看不到函数序列；本剧本的价值在 `observable_touchpoints`——它把"内部走到哪一步"翻译成"外部能观测到什么"，为族 agent 提供：
- **正向验证锚**：主干走通时，外部应出现哪些现象（收到 R2T、CLI 显示连接 live、IO 计数增长），用作 PASS 基线；
- **触发路径地图**：族 agent 据入口点反推"用什么外部手段（构造某类 PDU / 下发某 CLI）能驱动这条主干"，落到黑盒可执行的触发步骤；
- 后续剧本（分支枚举 / 异常传播）以本主干为骨架，标注"偏离主干处"，避免观测点重复盘点。
