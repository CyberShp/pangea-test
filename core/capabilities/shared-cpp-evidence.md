# 共享 C/C++ 源码取证底座

## 目标

对 C/C++ 混合的协议驱动、卡件驱动、微码和相关组件建立可核查的内部证据，再将其交给测试语义转译层。源码分析允许出现函数、变量、锁、计数器和回调；这些不是最终测试步骤。

## 必做取证面

1. **入口与调用链**：从协议入口、CLI/管理入口、回调注册和配置入口追踪 caller、callee、函数指针和共享状态影响。复用 `core/playbooks/调用链影响域.md`、`core/playbooks/主干追踪.md`。
2. **状态与分支**：提取建立、运行、受压、失败、恢复、销毁等状态及正常/错误分支。复用 `core/playbooks/状态机提取.md`、`core/playbooks/分支枚举.md`、`core/playbooks/异常传播.md`。
3. **资源与清理**：把内存、DMA 缓冲、队列槽位、连接、引用、锁、文件句柄、预留字段分别列账，核对申请、占用、归还和销毁路径。不能只按 grep 数量判断配对。
4. **并发与异步**：标出中断、软中断、工作队列、用户态线程、定时器、回调和销毁路径；检查共享状态的读写、同步、取消和 shutdown 顺序。复用 `core/playbooks/并发上下文识别.md`、`core/playbooks/初始化卸载时序.md`。
5. **量纲与时间**：定位规格上限、计数器、队列深度、重试、退避和超时的来源、校验和回落行为。复用 `core/playbooks/配置规格盘点.md`、`core/playbooks/超时重试盘点.md`。

## 取证纪律

- 代码事实必须给出仓库相对 `文件:行号`；无法静态闭环的关系记为 `【推测】`，并给出外部验证路径。
- C 与 C++ 边界需额外追踪对象所有权、构造/析构、异常或错误返回、回调注册和释放责任，不能假定 RAII 覆盖 C 资源。
- 动态分派、宏、硬件异步完成和跨仓调用无法确认时，写为覆盖缺口或开发确认项，不能编造调用关系。
- 源码仓只读。分析不修改源码、不生成修复代码、不运行会写入源码仓的索引或工具。

## 可迁移来源

本底座吸收通用 C/C++ 并发审查、所有权/错误清理和设备驱动审查的**方法**：寻找资源责任、错误出口、异步回调、生命周期交叠和上下文边界；不复制外部 skill 的角色设定或安装说明。完整来源与适用边界见 `core/capabilities/conditional-knowledge.md`。
