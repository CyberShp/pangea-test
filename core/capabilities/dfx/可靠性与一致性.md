# 可靠性与一致性能力包

## 关注问题

链路、设备、进程、盘、控制器或协议异常后，系统能否隔离影响、恢复业务、维持数据一致，并给出可观测和可操作的恢复路径。

## 代码信号与分析动作

- 超时、重试、退避、reset、failover、recovery、flush、journal、checksum、重放、错误码、健康状态和告警。
- 先定义稳态和业务不变量，再追踪故障扩散、降级、恢复和再次建立路径；检查恢复后数据、性能、资源和连接是否真正回归。
- 数据一致性必须用外部读回校验、校验和、协议语义或一致性观测验证，不能以“未崩溃”替代。

## NVIDIA 方法补充

仅在源码或任务材料命中 DOCA、BlueField、ConnectX、mlx 等证据时使用 `nvidia-doca-hardware-safety`、`nvidia-doca-debug`、`nvidia-doca-telemetry` 方法：

- 故障前记录硬件/业务稳态和关键 inventory，明确预期爆炸半径与恢复路径；涉及 reset/reboot 时确认存在可观测的恢复出口。
- 恢复后按 hardware state → telemetry → connection/resource → business/data 顺序验证，设备重新可见不能替代业务恢复。
- 遥测只作为恢复证据之一：先确认 counter capability、计数域和采样窗口，再与外部 I/O、连接和数据一致性结果闭环。

## 条件参考

Chaos/resilience 与 DOCA telemetry/hardware-safety 的稳态、爆炸半径、遥测和恢复方法可迁移；具体故障注入接口需以当前环境可用能力为准。
