# 并发与异常能力包

## 关注问题

并发外部操作、异步回调、超时、取消、错误返回和销毁是否能在任意交叠顺序下保持状态一致、资源可回收、业务可恢复。

## 代码信号与分析动作

- 锁、原子、RCU、条件等待、工作队列、定时器、中断、回调、取消、引用计数、`goto err` 和提前返回。
- 先建立执行上下文和共享状态地图，再检查锁边界、同步协议、TOCTOU、重复完成、取消与销毁竞态。
- 外部可制造的并发动作优先是并发建连/断链、并发 IO/配置、报文提前/延后、超时/复位交叠；需要精确窗口时提出插桩需求。

## NVIDIA 方法补充

仅在源码或任务材料命中 DOCA/RDMA、BlueField、ConnectX、mlx 等证据时使用 `nvidia-doca-rdma`、`nvidia-doca-debug` 方法：

- 补充追踪 QP/task/CQ/completion 的异步生命周期，重点检查 completion 与 timeout/reset/cancel/destroy 的交叠，以及 queue/permission 条件是否改变外部完成结果。
- 异常定位按环境 → runtime → driver → hardware 分层收集证据，明确区分“观测到的症状”和“已证实的根因”。
