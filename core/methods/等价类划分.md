# 等价类划分法

> 当输入域可按"系统对其处理方式相同"切成若干组时，同组内任取一个代表值即可，无需穷举——本方法把无限/庞大的输入域切成有限的有效等价类与无效等价类，每类取一代表，解决"要么漏测某类输入、要么在同类值上重复堆用例"的完备性问题。

本方法回答"怎么系统推导用例（保等价类覆盖完备性）"，不回答"哪类输入背后有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **输入域可按处理方式分组**：一个字段/参数的取值能划成"合法处理""按 A 规则处理""按 B 规则拒绝"等若干类。
- **有枚举/类别型输入**：传输类型、认证方式（CHAP/None）、SGL 类型、命名空间类型、告警级别等取值来自有限类别集。
- **有格式/协议族分类**：不同 PDU 类型、不同 opcode、不同 KV 数据类型走不同处理分支。
- **区间被规则切段**：数值不是只看边界，而是"某段走快路径、某段走慢路径、某段非法"。
- **穷举不可行**：取值空间大（如 32 位 opcode、任意长度名称），必须靠分组代表值压缩。

纯"临界点两侧"问题应改用边界值分析（二者常配合：先划类，再对每个有效类的边界补取点）。

## 操作步骤

1. **确定被划分的输入维度**：锁定测试点的每个独立输入字段/参数，逐个划分。
2. **划有效等价类**：按"系统预期正常处理且处理方式一致"聚类，每类给一句判定规则与外部可设定手段。
3. **划无效等价类**：按"预期被拒绝/忽略/降级"的原因聚类（越界、类型不支持、格式错、权限不足），一因一类，勿并成一大类。
4. **每类取代表值**：每个等价类取 1 个典型代表值出一条用例；无效类之间互不遮蔽——一条用例只违反一个类，避免多重无效互相掩盖真实处理路径。
5. **补类间可疑边界**：相邻类的分界处若模糊，交由边界值分析补点（衔接，不在此重复）。
6. **标覆盖目标**：每条用例标注它覆盖的"等价类 ID（有效/无效）"，供覆盖审计核对每类是否至少一条。

覆盖准则：弱等价类覆盖（每有效类各一次）为基线；无效类必须逐类单独覆盖（每条只含一个无效因子）。

## 存储领域示例：iSCSI 认证方式 / NVMe opcode / KV 值类型

- **iSCSI 登录认证方式（AuthMethod）**：有效类=`None`、`CHAP`（协商成功）；无效类=不支持的方法名、CHAP 密钥错、发起方要求 None 而 target 强制 CHAP。各取一代表值构造 Login PDU，观测 Login Response 的 Status-Class/Status-Detail。
- **NVMe 命令 opcode**：有效类=已实现的 admin/IO opcode（如 Read/Write/Identify）；无效类=保留 opcode、未实现 opcode、当前控制器不支持的可选特性 opcode。代表值各下发一条，观测返回的 Status Code（如 Invalid Command Opcode）。
- **KV 键值数据类型/长度类**：有效类=支持的值类型；无效类=超长键、空键、非法字符键、不支持的值编码。每类取一代表，观测 put/get 应答码。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 4 的代表值 + 设定手段：写清如何用外部工具把输入字段设为该类代表值（构造特定 opcode/AuthMethod 的 PDU、下发特定类型 KV 请求）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 步骤 2/3 的预期：有效类应被正常处理并有成功外部反馈；无效类应按规格拒绝/忽略并给出可观测错误码，严禁依赖内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 6 标注的"等价类 ID"，供覆盖审计核对每个有效/无效类是否齐全。
- **推导方法论** ← 回填裸方法名「等价类划分」（不写路径），标明该用例由等价类代表值系统推导，便于评审追溯完备性来源。
