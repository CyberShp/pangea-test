# 判定表覆盖法

> 当"多个条件的组合决定采取哪种动作"时，用判定表把条件桩 × 动作桩排成矩阵，每一列规则出一条用例，解决"条件很多、动作分支互相纠缠、漏掉某种条件组合对应的动作"的完备性问题。

本方法回答"怎么系统推导用例（保规则列覆盖完备性）"，不回答"哪条规则背后有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **有"若条件 A 且 B 且非 C，则动作 X"式业务规则**：多条件联合决定输出/动作。
- **规格文档呈条件-动作表或多重 if/else 链**：权限判定、命令合法性判定、状态+参数联合裁决。
- **动作是离散的几种**：接受/拒绝/静默忽略/降级/告警，由条件组合选定。
- **条件之间有语义耦合**：不是独立参数组合（那用数据组合），而是"这套条件真值 → 这个动作"的因果规则。
- **看到经验证的 `analysis_fragment` 回传的分支判定证据**，判定点聚合成"条件组→动作"结构。

若只关心组合出现频次（无明确动作映射）用数据组合测试；若聚焦单个判定点的真假用判定点覆盖。

## 操作步骤

1. **抽条件桩**：列全影响动作的输入条件（每条件先取布尔或等价类离散值）。
2. **抽动作桩**：列全可能的输出动作/响应。
3. **建判定表**：条件桩为行、规则为列，枚举条件真值组合（n 个布尔条件 → 最多 2^n 列），每列填对应动作。
4. **化简**：合并动作相同且仅一个条件不同的列为"-（无关）"，去掉不可达/矛盾组合，得精简规则集。
5. **每条规则出一条用例**：一列 = 一条用例，按该列条件真值用外部手段构造输入，观测是否得到该列规定的动作。
6. **补默认与遗漏规则**：显式为"规格未覆盖的条件组合"出一条用例，验证系统有安全默认动作（拒绝/忽略而非未定义行为）。
7. **标覆盖目标**：每条用例标注它覆盖的"规则列 ID"，供覆盖审计核对每列是否一条。

覆盖准则：每规则列至少一条用例为基线；化简掉的"-"需确认确实与动作无关。

## 存储领域示例：iSCSI 命令合法性裁决 / NVMe 访问控制

- **iSCSI 收到 SCSI Command 时的处置**：条件={会话在 FFP?、CmdSN 在窗内?、是否 Immediate?、LUN 有效?}；动作={正常执行、静默忽略、Reject、Check Condition}。判定表关键列：非 FFP → 协议错误关连；**CmdSN 超出 MaxCmdSN 窗且非立即 → MUST 静默忽略（不回 Reject，RFC 3720/7143）**；LUN 无效 → SCSI Check Condition。每列各构造对应输入观测应答。
- **NVMe 命名空间访问裁决**：条件={控制器已连接、命名空间已映射给该主机、opcode 支持、队列有效}；动作={执行、Invalid Namespace/Format、Invalid Opcode、终止}。逐列构造，观测 Completion 的 Status Code。
- **阵列管理面权限判定**：条件={角色、操作类型、对象锁定态}；动作={允许、拒绝、需二次确认}。逐列下发 CLI，观测回显与错误码。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 5 的条件真值构造：写清如何用外部手段把每个条件置为该列真值（构造特定 CmdSN/会话态/LUN 的命令、设定角色与对象态）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 该列规定的动作：系统应产生规则指定的外部动作（执行成功/特定错误码/静默无响应），判据外部可观测，严禁查内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"规则列 ID"，供覆盖审计核对判定表每列是否覆盖。
- **推导方法论** ← 回填裸方法名「判定表覆盖」（不写路径），标明该用例由判定表规则列系统推导，便于评审追溯完备性来源。
