# 状态转换法

> 当测试点的行为取决于"当前处于哪个状态"时，用状态迁移图系统性推导用例，保证每个状态、每条合法迁移、每个非法迁移都被覆盖——解决"用例覆盖了功能却漏掉状态时序"的完备性问题。

本方法回答"怎么系统推导用例（保状态覆盖完备性）"，不回答"该状态机有哪些风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **有显式状态机**：协议/驱动里存在命名状态（如 iSCSI 的 Free/XPT_WAIT/IN_LOGIN/LOGGED_IN，NVMe/TCP 的连接状态）。
- **有会话/连接生命周期**：建连→就绪→数据传输→拆连→回收，行为随生命周期阶段变化。
- **有"当前状态决定下一步是否合法"的语义**：同一操作在不同状态下结果不同（如未登录态收到 SCSI Command 应被拒绝）。
- **有超时/异常触发的隐式状态跃迁**：心跳超时、链路抖动导致状态自动回退或进入恢复态。
- **代码里出现 `switch(state)`、状态枚举、`fsm_transition()` 一类结构**（由 code-excavator「状态机提取」剧本回传的证据包提示）。

无上述信号（纯无状态的数值/格式校验）应改用边界值分析或等价类划分。

## 操作步骤

1. **建状态清单**：从证据包（状态机提取剧本产出）列全所有状态，含隐藏态（恢复中、半关闭、错误态）。每个状态标注"外部如何观测其存在"（CLI 回显、协议应答码、连接计数），因为黑盒不能读内部变量。
2. **建事件清单**：列全触发迁移的外部事件（收到某 PDU、下发 CLI、链路 down、定时器到期）。
3. **画迁移表**：行=状态，列=事件，格=迁移目标或"非法/忽略"。空格必须显式判定，不留白。
4. **推导合法迁移用例**：每条有目标的格 → 一条用例（在源状态施加事件，观测是否到达目标状态的外部特征）。
5. **推导非法迁移用例**：每个"非法/忽略"格 → 一条负向用例（观测系统是否正确拒绝且不进入错误态、不崩连）。
6. **推导序列用例**：串起关键路径（如 建连→登录→传输→注销），覆盖多步时序，验证状态按序推进。
7. **补环回与自迁移**：状态回到自身或成环（重连、重登录）的路径单独出例，易漏。
8. **标覆盖目标**：为每条用例标注它覆盖的"状态/迁移"，供覆盖审计核对是否全表覆盖。

覆盖准则（由弱到强，按场景深度选）：状态覆盖 < 单迁移覆盖（推荐基线）< 迁移对（两步序列）覆盖。

## 存储领域示例：iSCSI 会话状态机

以 iSCSI Full Feature Phase 前的会话状态迁移为例走一遍：

- **状态清单**：Free、XPT_WAIT（传输连接等待）、IN_LOGIN（登录协商中）、LOGGED_IN（全特性阶段）、IN_LOGOUT、CLEANUP_WAIT。外部观测手段：`iscsiadm -m session` 是否列出会话、Login Response PDU 的 Status-Class/Status-Detail、TCP 连接是否存活。
- **事件清单**：TCP 建连成功、收到 Login Request（含 CSG/NSG 阶段位）、协商参数非法、收到 SCSI Command、收到 Logout Request、心跳（NOP-Out/In）超时、TCP RST。
- **迁移表片段**：IN_LOGIN × "参数非法 Login" → 回 Login Response 带 Initiator/Target error 后拆连（非法迁移用例）；Free × "收到 SCSI Command"（未建连即下发）→ 忽略/拒绝（负向用例）；LOGGED_IN × "NOP 超时" → CLEANUP_WAIT（隐式超时迁移用例，需构造链路静默触发）。
- **序列用例**：建连→登录成功→下发读命令→Logout→会话消失，全程用抓包 + `iscsiadm` 回显观测。

同理，NVMe/TCP 连接状态机（icreq/icresp 建连协商→就绪→收发 Capsule→断连）可套同一流程：把 icreq 参数非法、就绪前下发 Command Capsule 等作为非法迁移逐格出例。

## 产出映射

每条推导出的用例填入 `templates/黑盒用例.md` 对应字段：

- **测试步骤/触发手段** ← 步骤 4–6 的"在源状态施加事件"：写清如何用外部手段把系统置于源状态、再施加事件（如"先 `iscsiadm` 建连登录，再构造非法 Login PDU 重发"）。
- **预期结果/观测判据** ← 目标状态的外部可观测特征，给出 PASS/FAIL 判据（应答码、会话是否存活、抓包应答），严禁写"检查内部状态变量"（R-7.2）。
- **优先级/关联风险** ← 由 lenses/ 透镜（如超时恢复、并发）标注，与本方法正交，不在此处产生。
- **覆盖目标** ← 步骤 8 标注的"状态/迁移 ID"，供覆盖审计核对迁移表是否全覆盖。
- **推导方法论** ← 回填本方法名「状态转换」，标明该用例由状态迁移表系统推导，便于评审追溯完备性来源。
