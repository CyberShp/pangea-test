# 处理周期测试法

> 当系统存在周期性处理（轮询、批处理、定时刷新、心跳、后台回收）时，缺陷高发于"周期边界、跨周期累积、周期与外部事件错位"；本方法围绕处理周期系统取观测点，解决"只测了单次触发、漏掉周期起止与跨周期状态"的完备性问题。

本方法回答"怎么系统推导用例（保周期覆盖完备性）"，不回答"周期机制背后有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **有定时/周期任务**：心跳（NOP-Out/In）、Keep-Alive、后台 GC/scrub、缓存刷盘周期、统计采样周期、告警去抖周期。
- **有批处理**：批量下刷、批量回收、批量上报，一批 N 个为一个处理周期。
- **有轮询**：轮询队列、轮询链路状态、轮询磁盘健康。
- **周期数与外部事件的相位关系影响结果**：事件恰好落在周期边界/周期间隙。
- **看到 excavator 超时与重试点盘点/资源生命周期证据包中出现定时器、周期计数**。

若关注的是单次超时时序竞争，用时间维度覆盖；若关注一次批处理内部的条件动作，用判定表。

## 操作步骤

1. **识别周期参数**：列出周期长度 T、批大小 N、触发条件、一个周期内的处理阶段，并标注外部如何观测"一个周期已发生"（统计刷新、心跳报文、告警产生/消除）。
2. **取周期计数点**：第 0 次（尚未触发）、第 1 次（首个周期）、第 N 次（稳定期）、跨很多周期（长稳累积）。
3. **取周期内相位点**：在周期开始、中段、结束/边界处施加外部事件，观测处理是否正确对齐（如"刷新前 vs 刷新后读到的统计值"）。
4. **构造跨周期累积用例**：连续多周期施加负载，观测是否有跨周期未清理的累积（未消费队列、未回收资源、统计溢出/回绕）。
5. **构造周期与事件竞争用例**：事件恰好落在周期边界（如断链恰好在心跳超时判定点），观测处置一致性。
6. **构造周期抑制/去抖用例**：告警去抖、抖动抑制类周期——短于周期的抖动应被抑制，跨周期的应上报。
7. **标覆盖目标**：每条用例标注覆盖的"周期点 ID（计数/相位）"，供覆盖审计核对周期起止与跨周期是否齐全。

覆盖准则：单周期正确 + 跨周期累积正确 + 周期-事件相位正确，三者齐为完整。

## 存储领域示例：iSCSI NOP 心跳 / 后台巡检 / 统计采样

- **iSCSI/NVMe 心跳周期**：以 NOP-Out/In（iSCSI）或 Keep-Alive（NVMe）周期为处理周期。构造"链路在一个心跳周期内静默→恰好超时"，观测是否按期进入恢复（iSCSI 进 CLEANUP_WAIT）；构造"抖动短于周期"观测不误判断链。
- **后台巡检/scrub 周期**：触发一轮巡检，观测告警在巡检周期后产生/消除；跨多轮观测巡检进度统计不回退、不重复告警。
- **统计采样周期**：性能统计每 T 秒刷新。在刷新边界前后各读一次，观测计数按周期推进、跨长时间无回绕异常；配合边界值分析验证计数器回绕点。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 2–6 的构造：写清如何用外部手段对齐周期施加事件（按心跳周期注入静默、连续多周期打流、在采样边界前后读统计）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 周期处理的外部现象：心跳超时按期触发恢复、跨周期无资源累积、统计按周期正确推进，判据外部可观测，严禁查内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜（如资源泄漏、超时恢复）标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"周期点 ID"，供覆盖审计核对周期计数与相位是否齐全。
- **推导方法论** ← 回填裸方法名「处理周期测试」（不写路径），标明该用例由处理周期取点系统推导，便于评审追溯完备性来源。
