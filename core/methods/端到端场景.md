# 端到端场景法

> 当被测行为跨越多个模块/多层协议/多个操作步骤才构成一次完整业务时，单点用例覆盖不到"链路串起来后的衔接与状态传递"；本方法沿真实业务链路系统构造端到端用例，解决"每个环节单测都过、整链跑通却断"的完备性问题。

本方法回答"怎么系统推导用例（保业务链路覆盖完备性）"，不回答"链路上哪个环节有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **一次业务跨多模块/多层**：主机→网络→前端协议→缓存→后端落盘的完整 IO 路径。
- **有多步操作序列构成用户目标**：建连→发现→登录→映射→读写→注销。
- **跨协议/跨管理面协同**：管理面下发配置 + 数据面生效验证；带内命令 + 带外 BMC 协同。
- **关注"整链正确"而非单接口**：数据从入口到落盘再读回的一致性。
- **看到 excavator 调用链与影响域证据包**呈现跨模块长链路。

单模块内部状态迁移用状态转换；单接口输入分类用等价类。本法专治"整链衔接"。

## 操作步骤

1. **画端到端链路**：列出一次完整业务的所有环节与经过的模块/协议层，标注每环节外部观测点（抓包点、CLI 回显、落盘校验点）。
2. **定义主场景（happy path）**：串起最典型的成功链路，逐步出一条端到端用例，全程外部观测每环节达成。
3. **派生替代场景**：对链路关键分叉点（不同协议、不同配置、不同路径）各派生一条端到端变体。
4. **注入链路异常**：在链路各环节注入故障（中途断链、某模块拒绝、超时），观测端到端是否优雅失败并可恢复（错误正确上报到入口、无中间态残留）。
5. **数据一致性贯穿校验**：写入端数据与读回端数据端到端比对（校验和/内容），确保跨模块搬运不损坏、不丢失、不错位。
6. **跨管理面/数据面协同**：管理面变更后在数据面验证生效（映射即通、解除即断），跨面时序正确。
7. **标覆盖目标**：每条用例标注覆盖的"链路 ID + 环节集"，供覆盖审计核对主链路与关键分叉是否齐全。

覆盖准则：主场景全链 + 每关键分叉一条 + 每环节异常一条为基线。

## 存储领域示例：NVMe/TCP 全链 IO / iSCSI 发现到读写 / 管理面到数据面

- **NVMe/TCP 端到端 IO**：主机 `nvme discover`→`nvme connect`（icreq/icresp 协商）→下发写 IO→阵列前端→缓存→后端落盘→读回校验。全程抓包看 Capsule 收发、CLI 看连接与命名空间、读回做校验和比对。注入"落盘阶段掉电"观测重启后数据一致。
- **iSCSI 发现到读写**：`iscsiadm` SendTargets 发现→登录（协商）→LUN 上线→文件系统读写→注销下线。派生 CHAP 认证变体、多路径变体各一条端到端用例。
- **管理面到数据面协同**：阵列 CLI 创建卷并映射给主机→主机 rescan 发现新盘→读写→CLI 解除映射→主机侧 IO 应端到端失败（Invalid Namespace/设备消失）。观测管理面操作到数据面生效的时序与一致性。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 2–6 的链路步骤：逐环节写清外部动作（discover/connect/IO/CLI 配置/故障注入），每步是黑盒同学真能执行的动作。
- **观测手段 + 观测判据（PASS/FAIL）** ← 每环节与端到端终态的外部现象：全链成功且读回数据一致、异常时优雅失败并正确上报、无中间残留，判据外部可观测，严禁查内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"链路 ID + 环节集"，供覆盖审计核对主链路与分叉是否齐全。
- **推导方法论** ← 回填裸方法名「端到端场景」（不写路径），标明该用例由业务链路系统推导，便于评审追溯完备性来源。
