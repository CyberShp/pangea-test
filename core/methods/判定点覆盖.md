# 判定点覆盖法

> 当行为由若干判定点（分支条件）控制、每个判定点又由多个子条件组成时，本方法针对每个判定点系统取真/假（及 MC/DC 级的子条件独立影响），解决"分支的某个方向或某个子条件从未被走过"的完备性问题。

本方法回答"怎么系统推导用例（保判定/条件取值完备性）"，不回答"哪个分支背后有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **excavator 分支枚举剧本回传了判定点清单**：明确的 if/switch/循环判定点及其条件表达式。
- **单个判定由复合布尔条件构成**：`if (a && (b || c))`，需要保证每个子条件都独立影响过判定结果。
- **关注"分支两个方向都走到"**：真分支、假分支、循环进入/不进入/边界次数。
- **测试点偏实现级分支覆盖**（灰盒证据充足），而非纯业务规则矩阵（那用判定表）。
- **有短路求值语义**：`&&`/`||` 的短路可能让某子条件从未被求值，需专门构造。

若是"多条件→多动作"的业务表用判定表覆盖；若是纯输入分类用等价类划分。

## 操作步骤

1. **列判定点清单**：从证据包取每个判定点及其条件表达式、真/假各自导向的外部行为。
2. **拆子条件**：把复合条件拆成原子子条件，标注短路关系。
3. **定覆盖强度**：判定覆盖（每判定真假各一次）为基线；条件覆盖（每子条件真假各一次）加强；MC/DC（每子条件独立翻转能改变判定结果）为高危路径最强级。
4. **为每判定构造真值输入**：找到能让判定取真、取假的外部输入组合，各出一条用例；MC/DC 时为每个子条件构造"仅它翻转导致判定翻转"的成对用例。
5. **映射到外部可观测差异**：确认真分支与假分支在外部现象上可区分（不同应答码/不同流控/不同日志告警），否则该分支黑盒不可判定，标注需灰盒旁证。
6. **补循环边界**：循环判定取 0 次/1 次/多次/上限次。
7. **标覆盖目标**：每条用例标注覆盖的"判定点 ID + 取值方向（真/假/子条件 ID）"，供覆盖审计核对。

覆盖准则：判定覆盖为下界，条件覆盖/MC/DC 按分支危险度升级。

## 存储领域示例：CmdSN 窗判定 / PDU 长度校验分支 / 重试判定点

- **CmdSN 窗判定点**：条件 `ExpCmdSN <= CmdSN <= MaxCmdSN`（含回绕比较）。真分支=入队处理；假分支=**非立即命令静默忽略（RFC 3720/7143，不回 Reject）**。构造窗内/窗外/回绕临界三类输入，外部观测"有无响应、会话是否受影响"区分分支。
- **PDU 长度校验判定**：`if (DataSegmentLength > MaxRecvDataSegmentLength)` 真分支=按协议终止/回错断连，假分支=正常收包。构造超限/临界/正常长度 PDU，观测连接是否存活与应答码。
- **异常重试判定点**：`if (retries < MAX && retriable_error)` 复合条件，MC/DC 构造"仅错误可重试翻转""仅次数耗尽翻转"两组，外部观测重传报文次数与最终失败上报。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 4 的真值输入构造：写清如何用外部手段造出让判定取真/取假的输入（构造窗内/窗外 CmdSN、临界长度 PDU、可重试/不可重试错误注入）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 步骤 5 的外部可区分现象：真/假分支应产生不同的外部结果，判据外部可观测，严禁查内部变量（R-7.2）；分支无外部差异时须标注为黑盒盲区。
- **关联风险** ← 由 lenses/ 透镜标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"判定点 ID + 取值方向"，供覆盖审计核对每分支/子条件是否覆盖。
- **推导方法论** ← 回填裸方法名「判定点覆盖」（不写路径），标明该用例由判定点真假取值系统推导，便于评审追溯完备性来源。
