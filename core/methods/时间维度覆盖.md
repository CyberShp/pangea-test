# 时间维度覆盖法

> 当行为随时间演化——超时、老化、时序竞争、长稳累积——时，静态单点用例覆盖不到"时间轴上才暴露的缺陷"；本方法沿时间维度系统构造用例（超时临界、并发时序、长时老化），解决"功能正确但在特定时序或长时间运行下崩坏"的完备性问题。

本方法回答"怎么系统推导用例（保时间维度覆盖完备性）"，不回答"时间相关行为背后有什么风险"（那是 lenses/ 的职责，尤其与超时恢复、并发透镜正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **有超时/定时器**：连接超时、命令超时、Keep-Alive/NOP 超时、重试退避。
- **有时序竞争**：两个外部事件的先后/并发导致不同结果（断链 vs 命令完成的竞争）。
- **有老化/长稳需求**：长时间运行下的资源累积、序号回绕、时钟漂移、缓存老化。
- **有先后依赖**：操作 A 必须在 B 之前/之后，乱序则异常。
- **看到经验证的 `analysis_fragment` 中的超时/重试盘点或并发上下文识别证据**。

若是固定周期性处理用处理周期测试；若是纯状态迁移用状态转换。本法专治"时间/时序/时长"三类时间维度。

## 操作步骤

1. **列时间敏感点**：枚举超时阈值、定时器、时序依赖对、长稳关注量（内存/连接/序号），标注外部如何施加时间控制与观测（延迟注入、抓包时间戳、长跑监控）。
2. **超时临界取点**：对每个超时阈值 T，取 T−ε（恰不超时）、T（临界）、T+ε（恰超时），观测超时是否按期触发且处置正确（与边界值分析在时间轴上衔接）。
3. **时序竞争排列**：对关键事件对，构造"A 先""B 先""几乎同时"三种时序，各出一条用例，观测结果一致且无损坏。
4. **乱序/延迟注入**：对有序依赖的操作/报文注入延迟或乱序，观测系统正确排序或拒绝。
5. **长稳老化用例**：长时间（小时/天级）持续负载，周期采样资源与序号，观测无泄漏、无回绕异常、无性能劣化（长稳的资源判据与资源泄漏透镜正交组合）。
6. **恢复时序**：故障→恢复的时间行为（重连退避、恢复超时、恢复期间新请求处置）。
7. **标覆盖目标**：每条用例标注覆盖的"时间点 ID（超时临界/时序排列/长稳里程碑）"，供覆盖审计核对时间维度是否齐全。

覆盖准则：每超时阈值三点 + 每关键事件对三种时序 + 一条长稳为基线。

## 存储领域示例：命令超时 / 断链竞争 / CmdSN 回绕 / 长稳

- **命令超时临界**：注入网络延迟使命令响应恰好落在超时阈值 T−ε/T/T+ε，观测主机侧是否按期判超时并重试/上报，target 侧连接与在飞 IO 是否受控。
- **断链 vs 命令完成竞争**：在命令即将完成的瞬间注入 TCP RST/静默断链，构造"完成先到""断链先到"两种时序，观测无重复完成、无数据损坏、无残留上下文（NVMe/TCP 异常断链路径尤需覆盖）。
- **CmdSN/序号回绕的时间维度**：长时间打流把 CmdSN 推到 0xFFFFFFFF 后回绕到 0，观测回绕后命令仍按序被接受（与边界值分析回绕点衔接，本法侧重"长时间跑到回绕"的时间路径）。
- **长稳老化**：连续多小时建断链+IO，周期采内存/连接计数/句柄，观测回落基线、无单调上涨、性能不劣化。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 2–6 的时间控制构造：写清如何用外部手段施加时延/乱序/长跑（网络延迟注入、精确时刻注入 RST、长稳压测脚本）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 时间行为的外部现象：超时按期触发、时序竞争结果一致无损坏、长稳资源回落无泄漏，判据外部可观测且尽量量化，严禁查内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜（如超时恢复、并发、资源泄漏）标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"时间点 ID"，供覆盖审计核对超时临界/时序排列/长稳里程碑是否齐全。
- **推导方法论** ← 回填裸方法名「时间维度覆盖」（不写路径），标明该用例由时间维度取点系统推导，便于评审追溯完备性来源。
