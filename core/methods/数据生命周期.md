# 数据生命周期法

> 当一份数据要经历"创建→读写→迁移/复制→老化→销毁/回收"的完整周期时，缺陷高发于阶段交界与异常中断；本方法沿数据生命周期各阶段与阶段转移系统出用例，解决"只测了增删改查单点、漏掉阶段衔接与残留/丢失"的完备性问题。

本方法回答"怎么系统推导用例（保生命周期阶段覆盖完备性）"，不回答"某阶段背后有什么风险"（那是 lenses/ 的职责，与本方法正交组合）。

## 适用特征（agent 识别信号）

看到测试点具备下列任一信号，就应选用本方法：

- **有持久化数据对象的完整周期**：卷/LUN、命名空间、快照、KV 键值、配置项、会话上下文的创建到销毁。
- **有数据搬迁/复制/分层**：迁移、镜像同步、冷热分层、重删/压缩后落盘。
- **有回收/销毁语义**：删除、trim/unmap、快照删除、空间回收、连接上下文释放。
- **关注"周期结束后是否干净"**：无残留、无泄漏、无幽灵引用；或"周期中途异常后数据是否一致"。
- **看到经验证的 `analysis_fragment` 中的资源生命周期配对证据**（创建/释放配对、引用计数）。

若关注的是内存/句柄等运行时资源的配对释放，本法与资源泄漏透镜正交组合（本法保阶段覆盖，透镜找泄漏风险）。

## 操作步骤

1. **画数据生命周期阶段图**：列全阶段（创建、初始化、读、写/更新、迁移/复制、老化、删除、空间回收），标注每阶段外部如何观测数据存在与内容（CLI 列举、容量统计、读回校验）。
2. **每阶段正向出例**：每阶段各出一条"正常完成"用例，观测该阶段外部特征达成。
3. **阶段转移出例**：相邻阶段的转移各出一条（如"写后迁移""删除后回收""快照后源卷改写"），观测转移后新旧数据一致性。
4. **中断/异常插入**：在每个阶段中途注入中断（断电/断链/进程重启），观测重启后数据处于一致状态（要么完成要么回滚，不半成品）。
5. **周期闭合校验**：走完"创建…删除…回收"整条链，观测终态干净——对象不再列出、容量归还、无残留引用。
6. **并发同对象**：并发对同一数据对象施加不同阶段操作（删除 vs 读、迁移 vs 写），观测隔离/串行化正确性（与并发透镜正交组合）。
7. **标覆盖目标**：每条用例标注覆盖的"生命周期阶段 ID / 阶段转移 ID"，供覆盖审计核对各阶段与转移是否齐全。

覆盖准则：每阶段 + 每相邻转移 + 一条闭合链为基线；异常中断按危险阶段加强。

## 存储领域示例：命名空间/卷 / 快照 / KV 键

- **NVMe 命名空间生命周期**：创建 NS→映射给主机→读写 IO→（可选）扩容/迁移→解除映射→删除→空间回收。各阶段用 `nvme-cli`+阵列 CLI 观测 NS 列举、容量统计、读回校验；在"删除后"观测主机侧 IO 得到 Invalid Namespace、阵列容量归还。
- **快照生命周期**：建快照→源卷改写（观测快照数据不变，COW 正确）→从快照恢复/克隆→删快照→空间回收。中途断电后重启观测快照链一致、无孤儿数据块。
- **KV 键生命周期**：put 创建→get 读回校验→update 覆盖→TTL 老化/主动 delete→空间回收。闭合校验：delete 后 get 返回 not found、容量统计回落。

## 产出映射

每条推导出的用例填入 `core/templates/黑盒用例.md` 对应字段（左端为模板精确字段名）：

- **外部触发手段 + 操作步骤** ← 步骤 2–6 的阶段操作：写清如何用外部手段驱动每个阶段与转移（CLI 创建/删除、下发 IO、注入断电/断链、并发下发）。
- **观测手段 + 观测判据（PASS/FAIL）** ← 各阶段/终态的外部特征：对象按期存在/消失、读回内容正确、容量正确归还、异常后无半成品，判据外部可观测，严禁查内部变量（R-7.2）。
- **关联风险** ← 由 lenses/ 透镜（如资源泄漏、数据完整性）标注，与本方法正交，不在此处产生（风险优先级在 SFMEA 的 S·O·D 承载，用例模板无独立优先级字段）。
- **覆盖目标** ← 步骤 7 标注的"阶段 ID / 阶段转移 ID"，供覆盖审计核对生命周期是否全覆盖。
- **推导方法论** ← 回填裸方法名「数据生命周期」（不写路径），标明该用例由生命周期阶段系统推导，便于评审追溯完备性来源。
