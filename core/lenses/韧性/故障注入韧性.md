# 故障注入韧性透镜（DFX 维度：韧性）

> 一句话：找"底层硬件/链路/部件故障时软件扛不住"的隐患——链路闪断、盘故障、控制器/端口失效、超时风暴下，软件必须优雅降级、正确恢复、不崩溃、不丢数据、不误报，而非连锁雪崩。

## 风险机理

存储阵列被要求在部件故障下持续服务（高可用是核心卖点）。韧性缺口在故障注入时暴露为崩溃、挂死、数据不一致、恢复不了或恢复过度。与"异常输入"（外部脏数据）不同，本透镜针对**下层故障事件**。典型成因：
- **故障未处理/处理不全**：底层返回错误（IO error、链路 down、DMA 超时）的返回值未检查或错误分支不完整。
- **清理路径缺陷**：故障触发的清理（断链、abort、failover）本身漏释放/双重释放/竞态（与资源泄漏、并发交叉）。
- **恢复不幂等/雪崩**：一处故障触发大面积重试/重连风暴，放大成全局不可用；恢复动作重复执行破坏一致性。
- **超时链联动**：单点超时未隔离，层层超时叠加导致整机挂死。
- **数据一致性破坏**：故障发生在写的中途，未保证原子/回滚，恢复后数据不一致或静默损坏。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理（示例锚点均为示意）：
- **底层返回值检查**：IO/DMA/网络下层调用（`.*_submit_io|dma_map|kernel_sendmsg|.*_read/.*_write`）的返回值与错误分支——是否每个错误码都有处理，有无"忽略返回值"。
- **故障事件回调**：链路/端口/盘状态回调（`.*_link_down|.*_error_handler|.*_reset|.*_timeout|eh_.*|nvmet_tcp_state_change`）中的清理与恢复逻辑是否完整、幂等。
- **清理竞态**：故障清理路径（`.*_release|.*_abort|.*_disconnect`）与正常 IO 完成路径的并发——是否有锁/引用保护，双重释放/UAF 风险（交叉资源泄漏/并发透镜）。
- **重试/退避控制**：`retry|reconnect|backoff|failover` 是否有次数上限、退避、抖动，避免风暴；恢复是否幂等。
- **一致性保护**：写路径故障点的原子性/回滚（`journal|barrier|commit|rollback|atomic`）——中途故障是否保证不半写。
- **免疫判断**：若对象不涉及下层硬件/链路交互、无持久状态，则给"免疫理由"。

## 典型历史缺陷

- （通用示意）NVMe/TCP 链路在 IO 进行中被强制 RST，目标端断链清理路径与正在完成的命令回收并发执行，双重释放 cmd 结构导致控制器崩溃（故障清理竞态）。
- （通用示意）单盘慢/超时未被隔离，触发全阵列命令层层超时与重试风暴，健康盘的 IO 也被拖挂，外部表现为整机 IO hang 而非单点降级。

## 黑盒触发手段

存储领域的故障注入手段：
- **链路故障**：拔纤/端口 down/注入 TCP RST/丢包/高延迟，单次与反复闪断，IO 进行中注入。
- **盘/部件故障**：拔盘、盘慢/超时、控制器重启/倒换、端口失效，单点与多点组合。
- **超时/abort 风暴**：制造命令超时、批量 abort、目标端重启，压清理与恢复路径。
- **故障+压力叠加**：满负荷 IO 下注入故障，最大化竞态与雪崩暴露面；反复注入-恢复循环跑长稳。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象（全部外部可观测）：
- **可用性（首要）**：单点故障下设备不崩溃、不整机挂死；故障域被隔离，健康路径/盘的 IO 继续（优雅降级），而非雪崩。崩溃或全局 hang = FAIL。
- **数据一致性**：主机侧读回校验——故障（尤其写中途）恢复后数据一致、无静默损坏、无半写。
- **告警**：故障应触发对应告警（链路/盘/端口），恢复后告警按预期清除；漏报或误报 = FAIL。
- **CLI 回显**：`show` 状态正确反映故障与恢复（连接/路径/盘状态迁移正确），故障计数合理。
- **性能统计**：故障期间降级、恢复后回升到基线；不应恢复不了或长期不回升。
- **日志**：打出规范的故障处理/恢复日志与正确错误码；不应出现 panic/双重释放/UAF 栈。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`（字段：用例编号/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论/覆盖目标/关联风险）。

- **用例雏形 1｜IO 中链路闪断优雅恢复**：预置满负荷 IO → 外部触发：IO 进行中注入 TCP RST/端口 down 并反复闪断 → 观测手段：可用性 + 告警产生/恢复 + 数据读回校验 + 性能回升 → 判据：不崩溃、故障隔离、告警正确、恢复后数据一致且性能回基线，崩溃/雪崩/数据不一致判 FAIL。推导方法论：状态转换（种子方法）/ 端到端场景（端到端 M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜（资源泄漏/并发交叉）。
- **用例雏形 2｜单点故障不雪崩**：预置多盘/多路径满负荷 → 外部触发：注入单盘慢/超时 → 观测手段：可用性（健康路径 IO 继续）+ 性能降级幅度 + 日志 → 判据：故障域隔离、健康路径不受拖累、无整机 hang。推导方法论：错误推测（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜（时延长尾交叉）。
