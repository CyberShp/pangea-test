# 数据完整性透镜（DFX 维度：可靠性）

> 一句话：找"写进去的和读出来的不是同一份数据"——校验和/CRC 未校或错校、DIF/DIX 保护信息断链、掉电/缓存导致写序颠倒、静默数据损坏（SDC）无人发现，最终用户拿到脏数据却毫无告警。

## 风险机理

存储系统的第一承诺是"数据不错、不丢、不乱序"。任何一处保护信息未生成、未校验或校验后不处置，都会让损坏悄无声息地穿透到用户。典型成因：
- **校验缺位/错位**：端到端保护（DIF/DIX、CRC、校验和）在某条路径上未生成或未校验；或按错误的偏移/长度校验，校验永远"通过"。
- **保护信息断链**：数据在模块间搬运（协议层→缓存→盘）时 PI（Protection Information）未随行透传，中途丢弃或重算掩盖了已发生的损坏。
- **写序/屏障错误**：`flush`/`FUA`/写屏障缺失或乱序，掉电后元数据与数据不一致（先更新指针后写数据）。
- **静默损坏无检出**：位翻转、错位写（misdirected write）、撕裂写（torn write）无背景巡检（scrub），损坏累积到读时才暴露甚至永不暴露。
- **重传/重组错误**：协议层乱序重组、重传去重出错，拼出一份"看似完整"的错误数据。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理：
- **校验生成/校验点**：`crc32|crc16|crc_t10dif|csum|checksum|blk_integrity|bio_integrity|t10_pi|dif|dix|guard|apptag|reftag`。逐一回答"谁生成、谁校验、校验失败怎么处置"。
- **校验失败处置**：定位校验函数返回值的 `if (err)`/`goto`，核对失败分支是否**真正拦截并上报**，而非仅打印日志继续放行（吞错见 `异常处理覆盖` 透镜）。
- **写序与屏障**：`REQ_FUA|REQ_PREFLUSH|blkdev_issue_flush|fsync|nvme_setup_flush|barrier`，核对元数据/数据更新顺序与掉电语义（先落数据再落指针）。
- **保护信息透传**：数据搬运路径（`memcpy|copy|sg_copy|dma`）前后 PI 是否随行，模块边界处是否 `strip`/`re-generate`（重算即掩盖）。
- **重组/去重**：`reassemble|reorder|dedup|CmdSN|reftag` 校验是否把逻辑块与其保护信息绑定校验。
- **免疫判断**：若对象为纯控制面、不承载用户数据、无落盘路径，则给"免疫理由"。

- （通用示意）NVMe/TCP C2HData 重组路径未校验 T10-DIF 的 Guard 字段（CRC 校验位），链路位翻转的坏块被当作正常数据返回主机，读回比对才发现。
- （通用示意）掉电保护路径缺 FUA（Force Unit Access，强制落盘），缓存中已确认的写在掉电后丢失，重启后元数据指向的数据块内容是旧值。

## 黑盒触发手段

存储领域从外部逼出完整性问题的手段：
- **写读回比对**：写入已知图案（顺序/随机/边界图案）后完整读回逐字节比对，覆盖对齐/非对齐、跨块、大 IO。
- **链路误码注入**：在 NVMe/TCP 或 iSCSI 链路注入位翻转/坏帧，验证 CRC/DIF 是否检出并拒绝坏数据。
- **掉电/异常断电**：IO 进行中拔电/触发掉电保护，重启后校验数据与元数据一致性、有无撕裂写。
- **乱序/重传扰动**：注入 TCP 乱序、重传、重复报文，验证重组后数据正确。
- **长稳巡检**：长时间读写后触发背景巡检（scrub），观察静默损坏检出。

## 观测判据（从 `core/shared/观测手段目录.md` 选手段）

判 PASS/FAIL 的外部现象：
- **数据面读回校验（第七类）**：主机侧读回与写入图案逐字节一致 = PASS；任意字节不符 = FAIL（本透镜首要判据）。
- **协议报文**：注入误码后应观测到协议层完整性错误响应（如 NVMe status code 中的完整性/CRC 类状态码、iSCSI reject PDU），坏数据应被拒而非静默返回。
- **告警**：应产生数据完整性/校验失败/坏块类告警；损坏发生却无告警 = FAIL。
- **错误码**：读到损坏块时应返回规格规定的介质/完整性错误码（如 Unrecovered Read Error）；返回"成功+脏数据" = 最严重 FAIL。
- **日志**：应出现 CRC/DIF 校验失败、坏块隔离日志；巡检应记录检出与修复计数。
