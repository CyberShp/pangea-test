# 资源泄漏透镜（DFX 维度：可靠性）

> 一句话：找"申请了却在某些路径上没释放"的资源——内存、连接/会话、引用计数、文件描述符、队列/DMA 缓冲——它们随运行时间单调累积，最终耗尽系统。

## 风险机理

存储底软长期在线（阵列 7×24 运行），任何"每次操作漏释放一点"的缺口都会被反复的建链/断链、下发/完成、探测/移除放大，最终耗尽内核内存、连接槽位或 fd，导致新连接建不上、IO 卡死乃至 OOM/宕机。典型成因：
- **异常分支漏释放**：正常路径 free 了，但 `goto err` / 提前 `return -ERRNO` 的错误分支跳过了某一级 free。
- **配对不对称**：`alloc`↔`free`、`get`↔`put`、`kref_get`↔`kref_put`、`socket`↔`sock_release` 只做了一半，或双重释放（use-after-free 的近亲）。
- **引用计数失衡**：并发下 refcount 增减不匹配，对象永不归零（泄漏）或过早归零（悬挂）。
- **建链/断链不幂等**：重复断链或断链竞争导致资源既没释放又不能再用（槽位泄漏）。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理：
- **申请点**：`kmalloc|kzalloc|vmalloc|kmem_cache_alloc|alloc_skb|dma_alloc|kref_init|get_task|sock_create|__sock_create|fget|nvmet_.*alloc|iscsit_.*alloc`。逐一回答"谁负责释放、在哪释放"。
- **异常分支漏 free**：看 `alloc` 之后到函数返回之间的所有 `goto <label>` / `return -E*` / `break`，核对每条错误路径是否覆盖了此前已申请的每一级资源（多级申请常见"跳过中间某级"）。
- **配对失衡**：`grep` 成对符号做计数对照——`kref_get`/`kref_put`、`.*_get(`/`.*_put(`、`refcount_inc`/`refcount_dec`、`mutex_lock`/`unlock`（锁也是资源）、`fget`/`fput`、`sock_hold`/`sock_put`。计数不等或分支不对称即嫌疑点。
- **连接/会话生命周期**：断链/关闭函数（`.*_release|.*_free_queue|.*_disconnect|.*_close|nvmet_tcp_release_queue|iscsit_close_connection`）里是否释放了建链时申请的全部资源（队列、缓冲、cmd 结构、socket、per-queue 内存）。
- **完成路径漏归还**：IO 下发分配的 cmd/请求结构（`.*_alloc_cmd`），在**所有**完成路径（正常完成、超时、abort、连接断开清理）上是否都归还到队列/内存池。
- **免疫判断**：若对象仅栈上局部、无堆申请、无引用计数、无长生命周期句柄，则给"免疫理由"（供全透镜浅扫一句话说明）。

- （通用示意）NVMe/TCP 建链握手在能力协商失败的错误分支只释放了 socket，漏释放 per-queue 命令缓冲，反复建断链后内核内存单调上涨。

## 黑盒触发手段

存储领域从外部把泄漏逼出来的手段：
- **反复建断链压测**：脚本循环建立/断开 NVMe/TCP 或 iSCSI 连接数千至数万次（正常断链 + 强制 RST/掉线断链混合），放大每次的微小缺口。
- **异常分支覆盖**：故意让建链失败（错误的能力参数、超规格队列深度、认证失败、中途注入 TCP RST），专打错误处理路径的漏释放。
- **长稳/soak**：持续 IO + 周期性连接扰动跑数小时至数天，观察资源是否单调累积。
- **故障注入**：链路闪断、目标端重启、命令超时/abort 风暴，触发清理路径。

## 观测判据（从 shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象：
- **CLI 回显**：`show connection`/`show session` 的连接/会话计数在"建 N 次断 N 次"后应回到基线；持续偏高 = FAIL。资源计数类查询（内存池、队列占用）不应单调上涨。
- **性能统计**：内存占用统计、句柄/fd 计数在稳态扰动下应平稳；单调上涨曲线 = FAIL。
- **告警**：不应出现资源耗尽类告警（内存不足、连接数达上限）；出现即 FAIL。
- **日志**：不应出现 `alloc failed`/`out of memory`/`too many open files`；断链清理日志应与建链日志配平。
- **错误码**：耗尽后新建连接返回的资源类错误码（如 `-ENOMEM`/`-EMFILE`）出现即已泄漏到临界。
