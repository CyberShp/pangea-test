# 恢复路径透镜（DFX 维度：可靠性）

> 一句话：找"崩了之后爬不起来或爬起来是坏的"——掉电/重启/进程崩溃后的日志回放、状态重建、一致性恢复是否正确且幂等，恢复本身会不会二次损坏、会不会卡死在中间态。

## 风险机理

存储系统必须假设随时掉电、重启、故障切换。恢复路径是"最少被执行、最难被测试、后果最严重"的代码：平时不走，一走就是数据存亡关头。典型成因：
- **回放不幂等**：日志/journal 重放对"已生效"的操作重复执行，或中断后再次恢复时重复应用，导致状态错乱。
- **中间态无兜底**：恢复在半途再次掉电/崩溃，留下"恢复了一半"的不一致态，下次启动无法识别与续做。
- **一致性重建错误**：元数据与数据、主副本与镜像、缓存与盘之间恢复后不一致（顺序错、丢更新、脏数据当有效）。
- **恢复顺序依赖**：多组件恢复有隐含时序（先建链再回放、先重放日志再开服），乱序导致用旧状态对外服务。
- **恢复即损坏**：恢复逻辑本身有 bug（错误地清零、错误地回滚已提交事务），把可救的数据救坏。
- **无进入/退出判据**：无法判断"是否需要恢复""恢复是否完成"，可能跳过恢复或提前开服。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理：
- **恢复入口**：`recover|replay|journal|redo|undo|crash|reboot|power.?loss|resync|rebuild|reconstruct|.*_init.*restore|dirty.?flag`。逐一回答"何时触发、幂等吗、失败/中断怎么办"。
- **幂等性**：回放循环是否用序列号/LSN/事务标记跳过已应用项；重复恢复是否安全（再次进入恢复入口的路径）。
- **中间态标记**:是否有"恢复进行中"持久标记及其清除时机；恢复中途崩溃后能否被识别续做。
- **一致性顺序**：恢复中数据/元数据的落盘与更新顺序，是否先重建数据再更新指针（同 `数据完整性` 写序）。
- **进入/完成判据**：`need_recovery|is_dirty|recovery_done` 类判据是否可靠；开服（对外接受 IO）是否严格在恢复完成之后。
- **掉电保护协同**：缓存/掉电保护（capacitor/BBU）刷盘与重启恢复的衔接，已确认写是否在恢复后可见。
- **免疫判断**：若对象无持久状态、重启即重来、无跨重启一致性诉求，则给"免疫理由"。

## 黑盒触发手段

存储领域从外部逼出恢复缺陷的手段：
- **掉电/异常断电循环**：IO 进行中反复拔电/触发掉电保护，重启后校验数据与元数据一致性；专打"恢复中途再掉电"。
- **进程/控制器崩溃注入**：kill 关键进程或强制控制器复位，验证重启/接管后恢复正确且对外服务时机正确。
- **HA 故障切换**：主控故障触发切换，验证接管方恢复完成前不对外提供脏服务、切换后数据一致。
- **重启一致性巡检**：重启后完整读回并比对，触发背景一致性检查。
- **恢复中扰动**：恢复窗口内注入二次故障（再掉电、链路闪断），验证幂等与续做能力。

## 观测判据（从 `core/shared/观测手段目录.md` 选手段）

判 PASS/FAIL 的外部现象：
- **数据面读回校验（第七类）**：掉电/重启/切换后读回与掉电前已确认写入的数据一致（已确认写不丢、未确认写不半落）= PASS；不一致或撕裂 = FAIL。
- **CLI 回显**：恢复后卷/连接/容量/一致性状态应回到自洽基线；恢复卡死在"recovering"不收敛 = FAIL。
- **告警**：应有恢复开始/完成、以及必要时的一致性修复告警；恢复完成告警缺失或长期不恢复的故障告警 = FAIL。
- **日志**：应出现 replay/recovery 的开始与完成日志、应用条目计数；无恢复日志却已开服 = 跳过恢复 FAIL。
- **协议报文/错误码**：恢复未完成期间对主机 IO 应给出忙/重试类响应而非返回脏数据；返回"成功+脏数据" = FAIL。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`（字段：用例编号/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论/覆盖目标/关联风险）。

- **用例雏形 1｜掉电后恢复数据一致**：预置写入已知图案并确认落盘 → 外部触发：IO 进行中拔电重启 → 观测手段：数据面读回比对 + 恢复日志/告警 + CLI 一致性状态 → 判据：已确认写不丢、无撕裂、状态收敛到自洽基线，任一不符判 FAIL。推导方法论：数据生命周期（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜、数据完整性。
- **用例雏形 2｜恢复中途二次故障可续做**：预置进入恢复窗口 → 外部触发：恢复过程中再次掉电/复位 N 次 → 观测手段：读回比对 + CLI 恢复状态收敛 + 日志幂等计数 → 判据：多次中断后仍恢复到一致态、无重复应用，卡死不收敛判 FAIL。推导方法论：状态转换。关联风险：本透镜。
