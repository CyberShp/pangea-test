# 并发透镜（DFX 维度：可靠性）

> 一句话：找共享数据在多执行流下的竞争与锁边界缺陷——无锁访问、锁粒度/顺序错误、检查与使用之间的窗口——它们只在特定时序下偶发，是最难复现也最致命的一类失效。

## 风险机理

存储底软并发密集：硬中断/软中断/内核线程/工作队列/多队列（MQ）per-cpu 上下文、用户态多线程管理面并存，同一份连接状态、队列、引用计数、统计量被多个执行流并发访问。缺陷成因：
- **共享数据无保护**：状态字段、计数器、链表在多上下文读写却无锁/无原子操作，产生撕裂读、丢失更新、链表损坏。
- **锁边界错误**：临界区太小（保护不全，状态检查后到使用前被改）、锁顺序不一致（AB/BA 死锁）、中断上下文用了会睡眠的锁。
- **TOCTOU 窗口**：`if (state == READY)` 与随后动作之间状态已被另一流改变（连接已断、cmd 已释放）→ use-after-free / 非法状态迁移。
- **引用计数与销毁竞争**：一个流正在用对象，另一个流把它 `put` 到零并释放。
- **完成 vs 清理竞争**：IO 完成回调与连接断开清理并发跑，双重完成或完成已释放的 cmd。

## 代码特征模式（给 excavator 的扫描指引）

风险扫描剧本对本对象的 grep/阅读指令，命中记 `文件:行号` + 机理：
- **执行流入口**：`irqreturn_t|.*_isr|tasklet|softirq|work_struct|INIT_WORK|kthread|queue_work|napi_|blk_mq_.*|pthread_create`。先列全对象涉及的并发上下文。
- **共享数据 + 保护缺失**：结构体中被多流访问的字段，检查是否有配套锁——`grep` `spin_lock|spin_lock_irqsave|mutex_lock|read_lock|rcu_read_lock|atomic_|refcount_|READ_ONCE|WRITE_ONCE`。有共享写但无上述保护 = 疑似竞争（标【推测】）。
- **锁边界过窄**：`unlock` 之后仍访问受该锁保护的数据；`state` 判断与使用之间存在 `unlock`/可睡眠调用。
- **锁顺序/死锁**：同一代码库中出现两把锁两种加锁顺序（A→B 与 B→A）；中断上下文用 `mutex_lock`（可睡眠）。
- **TOCTOU**：`if (.*state.*==` / `if (.*flag` 之后不在同一临界区内完成对该对象的操作。
- **销毁竞争**：`kref_put|.*_put|free` 与并发的取用点；`del_timer` 而非 `del_timer_sync`；无 `flush_work`/`cancel_work_sync` 的异步回调销毁。
- **免疫判断**：若对象单线程/单上下文访问、或全部共享访问均在同一把锁下，给"免疫理由"。

## 典型历史缺陷

- （通用示意）NVMe/TCP 多队列下 per-queue 的接收状态机字段在 softirq 收包与 workqueue 处理间无锁共享，高并发建链偶发状态错乱、队列卡死。
- （通用示意）IO 完成回调与连接断开清理并发，cmd 结构被双重归还，压力下偶发 use-after-free 崩溃。

## 黑盒触发手段

- **高并发压测**：大量并发连接 + 高 QD 多队列 IO，最大化时序交叠；多核绑定打散上下文。
- **扰动叠加**：IO 压力下并发注入连接建立/断开/复位，逼出"数据面 vs 控制面"竞争。
- **时序放大**：目标端引入随机时延/抖动，改变到达顺序，暴露顺序依赖；反复长时间跑（竞争偶发，需量取胜）。
- **故障注入并发化**：多连接同时超时/abort/掉线，触发清理路径与完成路径的并发。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

- **日志**：并发压力下不应出现内核 `BUG`/`WARN`/`oops`/`list corruption`；出现即 FAIL。（KASAN/lockdep 告警**仅调试版内核可用**——生产版阵列上该判据会空转，生产版以 `BUG`/`WARN`/oops/异常复位告警为准。）
- **CLI 回显**：并发建断链后连接/会话状态与计数应自洽（无"幽灵连接"、无状态卡在中间态）；不自洽 = FAIL。
- **告警**：不应出现队列卡死、IO 超时风暴类告警。
- **性能统计**：并发下 IOPS/时延应稳定，不应出现因锁争用/卡死导致的吞吐塌陷或长尾时延突刺。
- **错误码**：并发操作不应返回本不该出现的非法状态错误码（提示状态机被并发破坏）。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`。

- **用例雏形 1｜数据面控制面并发无损**：预置多队列高 QD IO 稳态 → 外部触发：并发脚本持续建立/断开若干连接（含强制复位）→ 观测手段：内核日志（生产版看 BUG/WARN/oops；调试版加 KASAN/lockdep）+ IOPS/时延统计 + CLI 连接状态 → 判据：无崩溃/告警、性能不塌陷、连接状态自洽，任一破坏判 FAIL。推导方法论：状态转换（并发事件序）+ 端到端场景（M3 待补）。关联风险：本透镜。
- **用例雏形 2｜并发断链幂等**：预置若干活动连接 → 外部触发：对同一批连接并发发起多次断开/复位 → 观测手段：CLI 计数 + 日志 → 判据：无双重释放告警、连接计数正确归零、无残留中间态。推导方法论：状态转换（非法/重复迁移）。关联风险：本透镜、资源泄漏。
