# 超时恢复透镜（DFX 维度：可靠性）

> 一句话：找超时/重试/恢复/HA 切换路径上的缺陷——超时后不重试或无限重试、恢复不彻底、切换丢数据或双主——它们决定故障发生后系统能否自愈，是黑盒故障注入的主战场。

## 风险机理

存储系统的价值在于"坏了能恢复"。超时是故障的第一信号，恢复路径又是最少被正常流量覆盖、最容易带 bug 的冷路径。缺陷成因：
- **超时缺失/过长**：无定时器或超时值过大，故障后长时间挂死（IO hang），上层感知不到。
- **重试策略缺陷**：不重试（本可恢复的抖动直接失败）、无上限重试（风暴/雪崩）、无退避（拥塞加剧）、重试不幂等（重复下发致数据错乱）。
- **恢复不彻底**：超时/断链后重连成功但状态未重建（CmdSN/序号未复位、队列未重建、未完成 IO 未重放或未回错），进入"半死"状态。
- **HA/主备切换缺陷**：切换超时、切换中 IO 丢失或双主（split-brain）写、切换后路径未收敛、故障回切震荡。
- **超时与并发/资源交织**：超时清理路径与正常完成竞争（见并发透镜），或超时路径漏释放资源（见资源泄漏透镜）。

## 代码特征模式（给 excavator 的扫描指引）

风险扫描剧本对本对象的 grep/阅读指令，命中记 `文件:行号` + 机理：
- **超时/定时器**：`timer_setup|mod_timer|schedule_delayed_work|.*_timeout|jiffies|msecs_to_jiffies|ktime_|keep_?alive|kato|wait_for_completion_timeout`。记录每个超时的**时长来源**（硬编码/配置/协议协商，如 NVMe KATO、iSCSI NOP 间隔）。
- **重试/退避**：`retry|retries|max_retries|.*_retry_count|backoff|resend|requeue|BLK_STS_.*|nvme_.*retry`。核对：有无上限？有无退避？达上限行为（回错/降级/断链）？是否幂等（重发是否可能重复副作用）。
- **恢复/重连**：`reconnect|.*_reconnect|error_recovery|reset_ctrl|nvme_reset|recovery|failover|.*_restart_queue`。核对重连后是否重建全部状态（序号复位、队列重建、未决 IO 处置）。
- **HA/切换**：`failover|failback|switchover|takeover|standby|active_?passive|split.?brain|fencing|quorum`。核对切换的超时、IO 屏障、双写防护、路径收敛。
- **超时后处置**：超时触发点到其动作（abort/断链/上报/静默丢弃）的路径；对未完成 IO 的处置（重放/回错/丢弃）。
- **免疫判断**：若对象无外部依赖、无定时器、无重试恢复语义（纯本地同步计算），给"免疫理由"。

## 黑盒触发手段

存储领域故障注入把恢复路径逼出来：
- **链路故障注入**：TCP 断链/RST、丢包、单向阻断、目标端 NIC down，触发超时→重连→恢复全链路。
- **时延/抖动注入**：注入接近超时阈值的时延，打超时边界（临界触发/不触发）。
- **目标端异常**：目标进程重启、控制器复位、慢盘（命令不响应），触发命令超时与 abort。
- **HA 切换编排**：主动/被动触发主备切换、切换中持续 IO、制造网络分区试 split-brain、故障回切压测。
- **重试风暴**：制造持续短时故障，观察重试是否有上限与退避、是否雪崩。

## 观测判据（从 shared/观测手段目录.md 选手段）

- **性能统计**：注入故障后 IO 应在**有界时间内**恢复（时延回落、IOPS 回升）；持续 hang / 长时间不恢复 = FAIL。重传率/重试计数应收敛而非发散。
- **告警**：故障应触发对应告警（链路故障/切换），恢复后告警应自动清除；无告警或告警不清 = FAIL。
- **CLI 回显**：重连/切换后连接、会话、路径状态应回到"已建立/正常"，序号/计数自洽；卡在中间态或双主 = FAIL。
- **日志**：应打出超时→重试(带退避)→恢复的完整轨迹；不应出现无限重试刷屏、恢复后仍报错。
- **错误码**：超时应返回规格规定的超时/重试耗尽错误码；恢复后新 IO 应返回成功。数据一致性校验（切换前后读回）不得出错。

## 用例骨架

> 格式见 `templates/黑盒用例.md`。

- **用例雏形 1｜断链后 IO 有界恢复**：预置稳态 IO → 外部触发：注入 TCP 断链维持 T 秒后恢复链路 → 观测手段：IOPS/时延统计 + 告警 + CLI 连接状态 + 日志 → 判据：断链触发告警、重连后 IO 在有界时间恢复、告警清除、无残留 hang，超时不恢复判 FAIL。推导方法论：状态转换（正常→故障→恢复）+ 时间维度覆盖。关联风险：本透镜、资源泄漏。
- **用例雏形 2｜超时阈值边界**：预置可调时延链路 → 外部触发：注入分别略小于/略大于超时阈值的时延 → 观测手段：日志(是否触发超时) + 错误码 + 性能统计 → 判据：小于阈值不误触发、大于阈值按规格触发重试并回错，行为与规格一致。推导方法论：边界值分析。关联风险：本透镜。
