# 异常处理覆盖透镜（DFX 维度：可靠性）

> 一句话：找"错误分支没人管"——返回值不检查、错误被吞（打日志就 return 0）、errno 覆盖、异常路径缺清理/缺上报，让本该失败的操作"看起来成功"，故障被埋进系统深处。

## 风险机理

存储底软的每一次 `alloc`、每一条协议交互、每一次下盘都可能失败。异常处理不是可选项：漏处理一个错误分支，故障要么被静默吞掉（用户拿到假成功），要么在错误状态上继续执行（雪崩到更深的破坏）。典型成因：
- **返回值不检查**：调用可能失败的函数后不判返回值，直接用其产出（空指针解引用、用未初始化数据）。
- **吞错（swallow）**：捕获/判出错误后仅 `printk` 就 `return 0`/继续，向上层谎报成功。
- **errno/错误码覆盖**：多级调用中内层错误码被外层无条件重置，真实失因丢失，上层据错误码决策失误。
- **异常路径缺清理**：错误分支未回滚已修改的状态/未释放已占资源（与 `资源泄漏` 透镜互补）。
- **错误分支缺上报**：内部处理了错误但不产生告警/日志/错误码，外部完全不可见（可服务性盲区）。
- **默认分支缺失**：`switch` 无 `default`、状态机未知事件无兜底，非法输入走进未定义行为。

## 代码特征模式（供 context-pack obligation 使用的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理：
- **返回值未检**：定位可失败调用（`.*_alloc|copy_from_user|copy_to_user|kstrtoul|.*_submit|.*_send|nvmet_.*|iscsit_.*`）后是否紧跟 `if (ret)`/`if (!ptr)` 判断；未判即嫌疑。
- **吞错模式**：`grep` `return 0`/`return` 紧邻 `printk|pr_err|dev_err|WARN` 而无向上传播错误码——打印即"处理完"是典型吞错。
- **错误码覆盖**：多级函数中 `ret = ` 在错误分支后被无条件重新赋值（`ret = 0`）或用外层常量码覆盖内层真实码。
- **默认分支/兜底**：`switch (state|opcode|event)` 是否有 `default`；状态机 `handle_*` 对非法/意外事件是否有拒绝路径。
- **异常路径对称性**：错误 `goto`/提前 `return` 是否回滚了此前的状态变更（引用、计数、链表挂接、锁）。
- **上报缺位**：错误分支是否至少产生一处外部可观测证据（告警/日志/错误码之一）；三者皆无即"静默失败"。
- **免疫判断**：若函数无可失败调用、无外部输入、纯计算，则给"免疫理由"。

## 典型历史缺陷

- （通用示意）iSCSI 登录参数协商中 `kstrtoul` 解析失败分支被吞（仅打印后按默认值继续），非法协商参数被当合法接受，后续连接行为异常且无错误码可查。
- （通用示意）NVMe/TCP 命令处理 `switch (opcode)` 缺 `default`，未知/非法 opcode 未被拒绝也未上报，主机侧只见命令超时而无协议层拒绝状态码。

## 黑盒触发手段

存储领域从外部逼出异常处理缺口的手段：
- **非法输入注入**：构造越界/非法/超规格的协议字段、CLI 参数、配置值，专打输入校验与错误分支。
- **故障注入**：链路闪断、目标重启、命令超时/abort、资源耗尽（满队列/满连接），触发各类失败路径。
- **能力协商异常**：故意用不支持的能力、错误的队列深度/PDU 长度建链，验证失败是否被正确拒绝并上报。
- **边界与竞态**：并发下发+断链、极限参数值，逼出被忽略的意外事件分支。

## 观测判据（从 `core/shared/观测手段目录.md` 选手段）

判 PASS/FAIL 的外部现象：
- **错误码**：非法输入/失败操作应返回规格规定的错误码（协议层拒绝状态码、CLI 报错）；返回"成功"或超时而非明确拒绝 = FAIL（吞错特征）。
- **协议报文**：非法请求应有明确错误响应（NVMe status code、iSCSI reject PDU），而非静默丢弃或假成功。
- **告警 + 日志**：异常路径应打出预期错误日志/告警，错误码正确；异常发生却无任何日志/告警 = 静默失败 FAIL。
- **CLI 回显**：故障后状态查询应如实反映失败（连接失败/离线），而非仍显示"正常/已建立"。
- **性能统计**：错误计数/拒绝计数类统计应随注入递增；纹丝不动说明错误未被记账。
