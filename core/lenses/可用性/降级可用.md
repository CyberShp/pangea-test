# 降级可用透镜（DFX 维度：可用性）

> 一句话：找"部分故障却全盘拒绝服务，或降级降得不体面"——本可退化为只读/低速/子集服务时却直接全断；或降级时状态不透明、不告警、无法自动回升，甚至降级路径本身有 bug 把可用的也拖坏。

## 风险机理

理想系统在部分故障下应"优雅降级"而非"脆断"：缓存掉电保护失效→转直写、一条链路坏→降带宽、部分盘故障→只读/子集可用。降级透镜找的是"本可降级却没降、降了却不体面"的缺口。典型成因：
- **脆断而非降级**：部分资源故障（缓存、一条链路、部分节点）被当作致命错误，整体停服，而非退化到可用子集。
- **降级不透明**：进入降级态无告警、无状态标识，用户以为全速正常，据此误判（如写缓存失效已转直写但性能骤降无人知）。
- **降级即劣化全局**：降级逻辑串行阻塞、持锁过久、反复重试，把未故障的部分也拖入慢/停（连锁反应）。
- **无自动回升**：故障恢复后系统不自动退出降级态，长期停留在低性能/只读，需人工干预。
- **降级路径未测**：降级分支是低频代码，常见"降级时才暴露的空指针/死锁/数据错"。
- **降级语义错误**：该只读却仍接受写、该拒绝新连接却仍握手，降级承诺与实际行为不符。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理：
- **降级判定与切换**：`degrade|fallback|read.?only|ro_mode|write.?through|writethrough|safe.?mode|limp|partial|reduced`。逐一回答"何时进入、进入后行为如何变、如何退出"。
- **脆断嫌疑**：部分资源故障处是否直接 `return -EIO`/停服，而非切换到退化路径；缺 fallback 分支即嫌疑。
- **缓存/掉电保护降级**：`writeback→writethrough`、`cache_disable`、BBU/capacitor 失效处理，是否转直写并上报而非停写。
- **降级态可见性**：进入降级是否产生告警/日志/状态标识（供 CLI 查询）；无外部证据即"静默降级"。
- **连锁阻塞**：降级路径是否持全局锁、同步等待、无界重试，可能把健康部分拖慢（与 `过载保护` 相邻）。
- **回升逻辑**：故障恢复后是否有自动退出降级的路径及其触发条件；缺失则永降。
- **免疫判断**：若对象为原子操作、无部分可用语义（要么全成要么全败且无中间态价值），则给"免疫理由"。

## 黑盒触发手段

存储领域从外部逼出降级缺陷的手段：
- **部分资源故障注入**：使缓存/掉电保护失效、断部分链路、下线部分节点/盘，验证系统退化到可用子集而非全停。
- **降级态验证**：进入降级后下发读/写，验证降级语义正确（如只读态拒写、直写态仍可写但降速）。
- **故障恢复回升**：注入故障→恢复，验证系统自动退出降级、性能回升。
- **降级路径压测**：降级态下持续 IO，暴露低频降级分支的死锁/崩溃/数据错。
- **连锁探测**：仅对部分组件施故障，观察健康组件性能是否被无辜拖累。

## 观测判据（从 `core/shared/观测手段目录.md` 选手段）

判 PASS/FAIL 的外部现象：
- **性能统计**：部分故障后应保留可用服务（IOPS/带宽下降但不归零），健康部分不被拖垮；整体归零 = 脆断 FAIL。
- **告警**：进入降级态应产生"降级/性能受限/缓存保护失效"类告警，恢复后清除；静默降级（无告警）= FAIL。
- **CLI 回显**：应能查询到降级状态标识（只读/直写/子集可用）与受影响范围；显示"全部正常"却已降级 = FAIL。
- **协议报文/错误码**：降级语义应正确外显——只读态写请求返回规格规定的只读/拒绝错误码，而非静默丢弃或假成功。
- **数据面读回校验（第七类）**：降级期间读回数据仍正确（降速不降正确性）；返回脏数据 = 最严重 FAIL。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`（字段：用例编号/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论/覆盖目标/关联风险）。

- **用例雏形 1｜缓存保护失效转直写不停服**：预置写缓存开启 + 持续 IO → 外部触发：注入掉电保护/capacitor 失效 → 观测手段：性能统计（IOPS 不归零）+ 降级告警 + CLI 状态 → 判据：转直写继续服务、有降级告警与状态标识、读回正确；全停或静默判 FAIL。推导方法论：端到端场景（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜、降级可用。
- **用例雏形 2｜降级后自动回升**：预置部分故障进入降级态 → 外部触发：解除故障 → 观测手段：性能统计回升 + 告警恢复 + CLI 状态复位 → 判据：自动退出降级、性能回稳、告警清除；长期滞留降级判 FAIL。推导方法论：状态转换。关联风险：本透镜。
