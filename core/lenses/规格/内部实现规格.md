# 内部实现规格透镜（DFX 维度：规格）

> 一句话：找"实现自定义的上限/约束/校验没落实或超限行为不当"的隐患——队列深度、连接数、PDU/SGL 长度、会话数、缓冲上限等规格书承诺的边界，必须校验、必须在越限时给出规范且一致的行为。

## 风险机理

除对外标准外，阵列规格书还承诺一批**实现自定义上限与约束**（最大连接数、最大队列深度、单 PDU/单命令最大长度、最大会话/命名空间数、超时值等）。风险在于：声称支持 N 却在 N 或 N+1 处出问题，或越限时行为不规范（崩溃/静默截断/不一致错误码）。典型成因：
- **上限未校验**：接受超过规格上限的请求（超长 PDU、超深队列、超数连接），越界写/溢出。
- **临界off-by-one**：恰好在上限值 N 处拒绝（应接受）或 N+1 处接受（应拒绝）。
- **越限行为不规范**：超限时崩溃/挂死，而非规范拒绝并返回约定错误码；或静默截断导致数据错。
- **多资源上限不一致**：文档、代码常量、实际行为三者上限值不一致。
- **默认值/协商值越界**：协商结果落到规格外仍被接受。

## 代码特征模式（供 context-pack obligation 使用的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理（示例锚点均为示意）：
- **上限常量定义**：`MAX_|_MAX|LIMIT|MaxConnections|MaxCmds|MaxRecvDataSegmentLength|MAXH2CDATA|MaxBurstLength|MaxOutstandingR2T|nr_queues|queue_depth` 定义点——记录值，与规格书逐一比对（含单位）。
- **校验点**：上述上限在入口的检查（`if (.* > MAX|>= LIMIT)`）——是否存在、比较运算符是否 off-by-one、缺校验的路径。
- **长度/深度使用点**：`memcpy|alloc(len)|idx <|for (i<n)` 用到长度/深度/索引处——是否可被外部输入越过上限撑爆缓冲/越界。
- **越限分支行为**：超限时走 `return -E*`/`reject`/`BUG_ON`/`panic`/静默 `truncate`——判断是规范拒绝+错误码，还是崩溃/静默截断。
- **协商钳制**：协商/配置路径是否把结果 clamp 到 [min,max]（`clamp|min(|max(`）；越界值是否被拒绝或被安全钳制。
- **免疫判断**：若对象无外部可控的量纲输入、无自定义上限约束，则给"免疫理由"。

## 典型历史缺陷

<!-- 团队回填：历史缺陷案例 -->
- （通用示意）目标端声称支持某最大队列深度，但在恰好达到该深度（临界 N）时错误拒绝合法命令（off-by-one），主机侧表现为满队列时偶发命令失败。
- （通用示意）NVMe/TCP 目标端未校验单个 H2CData PDU 数据长度超过协商的 MAXH2CDATA（最大主机到控制器数据长度），越限 PDU 触发越界拷贝，连接异常复位甚至控制器重启。

## 黑盒触发手段

存储领域把内部上限压到边界的手段：
- **边界值扫描**：把连接数/队列深度/PDU 长度/会话数等参数取 N-1、N、N+1（规格上限附近）分别测试。
- **超规格请求**：构造超过规格上限的 PDU 长度、突发长度、未协商就发大 IO，专打越限分支。
- **满配打压**：把资源用到规格声称的满配（最大连接、最大命名空间、最大深度）并持续跑 IO，验证满配可用性。
- **协商越界**：登录/协商阶段提出规格外的参数取值，验证被规范拒绝或安全钳制。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象（全部外部可观测）：
- **错误码**：越限请求应返回规格约定的错误码（协议层/CLI 层），且各越限场景码值一致、可预期；崩溃或返回随机/无错误码 = FAIL。
- **CLI 回显**：满配（达规格上限）应能正常建立与查询；`show` 计数与规格上限一致；上限值不应与文档矛盾。
- **协议报文**：抓包确认越限 PDU 被规范拒绝（返回约定 reject/status），而非静默丢弃或错误接受后数据错乱。
- **告警/日志**：越限应打出规范的告警/日志并含正确错误码；不应出现崩溃栈、越界访问日志。
- **可用性交叉**：越限或满配后设备不崩溃、不挂死，合法业务仍可继续（越限行为不伤及无辜）。

## 用例骨架

- **用例雏形 1｜规格上限边界正确**：预置目标端与规格上限值 N → 外部触发：连接数/队列深度/PDU 长度取 N-1、N、N+1 → 观测手段：错误码 + CLI 计数 + 抓包响应 → 判据：≤N 接受、>N 规范拒绝并返约定错误码，off-by-one 或崩溃判 FAIL。推导方法论：边界值分析（种子方法，直接适用）。关联风险：本透镜。
- **用例雏形 2｜满配可用性**：预置目标端 → 外部触发：资源用到规格满配并持续跑 IO → 观测手段：CLI 满配状态 + 性能统计 + 告警 → 判据：满配可建可用、性能不崩、无资源类告警，达标即 PASS。推导方法论：等价类划分 / 处理周期测试（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜（资源争用交叉）。
