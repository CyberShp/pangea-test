# 对外规格符合性透镜（DFX 维度：规格）

> 一句话：找"对外协议/接口行为偏离 RFC/标准/规格书"的隐患——字段编码、状态码、时序握手、必选特性、错误响应必须与标准逐条对齐，任何"我方自定义解释"都可能与合规主机/交换机互通失败。

## 风险机理

阵列对外接口（NVMe/TCP、iSCSI RFC 7143、NOF、标准 CLI/管理接口）是与第三方主机、OS 原生 initiator、交换机互通的契约。任何偏离标准的实现都会在异构互通时暴露：合规对端按标准发/收，我方却按"自解释"处理，导致建链失败、字段误解、错误码不被识别。典型成因：
- **必选特性缺失/可选当必选**：标准规定 MUST 的未实现，或把 MAY/SHOULD 当强制拒绝合规对端。
- **字段编码/字节序错误**：多字节字段大小端、保留位、对齐、单位（字节/块/4KB 单元）与标准不符。
- **状态码/错误响应不合规**：返回非标准状态码，或标准规定的错误场景返回了错误的码/无响应。
- **时序/握手偏差**：登录/协商 PDU 顺序、参数协商（key=value）取值、协商未达成时的行为偏离标准。
- **越界处理不符规格**：标准规定"越窗静默忽略非拒绝"却发拒绝，或反之。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理（示例锚点均为示意）：
- **PDU/报文编解码**：`.*_parse|.*_build|.*_encode|.*_decode|ntohl|htonl|be32|le32|__packed` 处理协议头字段——逐字段核对偏移、长度、字节序、单位、保留位是否与 RFC/规格一致。
- **状态码/错误响应表**：`status|rsp_code|reject|reason|sense|FES|SC` 等常量定义与返回点——对照标准码表，成对写"数值+名称"核对。
- **握手/协商**：登录与能力协商路径（`.*login|.*negotiat|ICReq|ICResp|key.*value|MaxRecvDataSegmentLength|MAXH2CDATA`）——参数取值范围、默认值、协商失败行为是否合标准。
- **必选特性开关**：`support|capable|feature|MUST|mandatory` 相关分支——标准 MUST 项是否可被关闭或未实现。
- **边界/越界响应**：序列号窗口、长度上限的越界分支（`CmdSN|ExpCmdSN|MaxCmdSN` 越窗处理）——是否符合"标准规定的忽略/拒绝语义"。
- **免疫判断**：若对象为纯内部私有接口、不对外暴露、无标准约束，则给"免疫理由"（转由"内部实现规格"透镜覆盖）。

- （通用示意）iSCSI 目标端对 CmdSN 越出命令窗（大于 MaxCmdSN）的 PDU 返回 Reject，而 RFC 7143 规定应静默忽略（数值语义：CmdSN 越窗静默忽略、非拒绝），导致某合规 initiator 误判连接异常并断链。
- （通用示意）NVMe/TCP 目标端对 Header Digest 校验失败未按规范以 TCP_Term_Req（FES=3h，Header Digest Error）终止连接，而是直接静默丢弃，合规主机侧无法感知错误原因，表现为莫名超时。

## 黑盒触发手段

存储领域验证对外合规的手段：
- **标准 initiator 互通**：用 OS 原生 initiator（Linux nvme-cli/open-iscsi、Windows/VMware 原生栈）建链跑 IO，验证与合规实现互通。
- **协议一致性/合规套件**：跑协议一致性测试集、标准握手用例，逐条比对字段与状态码。
- **构造标准边界报文**：按 RFC 构造越窗、保留位置位、可选特性开关等合规但边界的报文，验证响应符合标准语义。
- **异构对端矩阵**：多种主机 OS / HBA / 交换机组合建链互通，暴露自解释偏差。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象（全部外部可观测）：
- **协议报文**：抓包逐字段比对——字段编码/字节序/单位、握手 PDU 时序、状态码取值必须与 RFC/规格一致；返回非标准码或错误响应类型即 FAIL。
- **错误码**：命令/操作在标准规定场景返回标准规定的错误码（协议层/CLI 层）；码值或语义不符 = FAIL。
- **CLI 回显**：与标准 initiator 建链应显示已建立、参数协商结果落在标准范围。
- **告警/日志**：合规交互不应产生协议违例告警；日志中的协议错误码应与标准一致。
- **互通结果**：多种合规对端均能建链、跑 IO、正常断链；仅我方自家 initiator 能通、标准 initiator 不通 = 合规缺陷 FAIL。

- **用例雏形 1｜标准 initiator 互通合规**：预置多种 OS 原生 initiator → 外部触发：各自建链、协商、跑 IO、断链 → 观测手段：抓包字段/状态码 + CLI 建链状态 → 判据：字段编码与握手时序合 RFC、状态码合规、互通成功，任一偏离判 FAIL。推导方法论：判定表覆盖 / 端到端场景（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜。
- **用例雏形 2｜边界报文响应符合标准语义**：预置目标端 → 外部触发：构造 CmdSN 越窗、Header Digest 错误等合规边界报文 → 观测手段：抓包响应类型 + 错误码 → 判据：越窗静默忽略（非拒绝）、Digest 错误按 FES=3h 终止，语义与 RFC 一致。推导方法论：边界值分析（协议边界）。关联风险：本透镜（异常输入健壮性交叉）。
