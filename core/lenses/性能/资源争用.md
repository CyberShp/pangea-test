# 资源争用透镜（DFX 维度：性能）

> 一句话：找"多执行流抢同一份有限资源"的瓶颈——锁、CPU、内存带宽、队列槽位、缓冲池、DMA/网卡队列、doorbell——争用点一旦饱和，吞吐封顶、时延突增、扩展性失效。

## 风险机理

与"性能退化（路径变长）"、"时延长尾（停顿抖动）"互补，本透镜聚焦**共享有限资源的竞争与饱和**。争用点是可扩展性的天花板：加核、加连接不再涨性能，甚至因争用开销倒退。典型成因：
- **锁争用**：热锁（全局队列锁、内存池锁、统计锁）被多核高频争抢，cache line 弹跳、自旋空转。
- **CPU/软中断集中**：所有中断/软中断/completion 落在单核（未做 RSS/中断亲和分散），单核饱和而其他核闲置。
- **内存带宽/拷贝争用**：数据面多流并发拷贝/校验，内存带宽饱和；NUMA 跨节点访问放大。
- **队列/槽位耗尽**：命令 tag 池、R2T 槽（MaxOutstandingR2T）、连接槽、缓冲池被抢空，后续请求排队或被拒。
- **doorbell/环形队列争用**：多生产者共享一条提交队列/环，尾指针 CAS 争用。
- **false sharing**：多核频繁写的计数落在同一 cache line。

## 代码特征模式（供 context-pack obligation 使用的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理（示例锚点均为示意）：
- **热锁定位**：数据面高频路径中的 `spin_lock|spin_lock_irqsave|atomic_|cmpxchg`；标注锁保护的资源、访问频度、是否可 per-CPU/per-queue 拆分。
- **共享有限池**：`.*_pool|tag|MaxOutstandingR2T|MaxCmds|free_list|mempool|dma_pool` 的申请/归还路径；池大小是否随并发可配、耗尽时的行为（阻塞/拒绝）。
- **中断/亲和集中**：`request_irq|irq_set_affinity|napi|RSS|smp_affinity` 配置——所有队列中断是否绑到单核；completion 是否单线程收口。
- **全局计数/统计**：多核写的 `g_stats|atomic64_inc|percpu?` ——是否 per-CPU 化，或存在 false sharing / cache line 弹跳。
- **NUMA/带宽**：跨节点内存申请（`kmalloc_node|numa`）与数据面拷贝量；跨 NUMA 访问放大点。
- **免疫判断**：若对象为独占资源、单流、无共享有限池，则给"免疫理由"（无争用面）。

- （通用示意）NVMe/TCP 目标端所有队列的 socket 收包软中断绑定到单一 CPU，多连接高负载下该核 100% 饱和成为瓶颈，其余核空闲，总吞吐卡死在单核上限。
- （通用示意）iSCSI 命令 tag 池全局共享且偏小，多主机深队列并发时 tag 频繁耗尽，新命令排队等 tag 归还，外部表现为吞吐封顶、时延抬升。

## 黑盒触发手段

存储领域从外部把争用逼出来的手段：
- **多流并发加压**：多主机/多连接/多队列同时满负荷，制造对共享池、锁、中断核的最大竞争。
- **核数/亲和对照**：对比单队列 vs 多队列、绑核 vs 不绑核的吞吐曲线，定位单核饱和/中断集中。
- **池容量边界**：把并发 IO 数逼近/超过 tag 池、R2T 槽（MaxOutstandingR2T）、连接上限，观察排队与拒绝行为。
- **大 IO 带宽压测**：大块顺序并发打满内存/网络带宽，观察带宽饱和后时延与公平性。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象（全部外部可观测）：
- **性能统计**：多流扩展时吞吐应线性上升至硬件上限；出现远早于硬件上限的平台期/回退 = 争用瓶颈 FAIL。队列深度统计不应长期堆积（池耗尽征兆）。
- **CLI 回显**：`show performance`/资源占用统计中，连接/队列/池占用应均衡；单点满载而整体未满 = 争用不均。
- **告警**：不应出现资源耗尽/背压类告警（tag 耗尽、缓冲不足）。
- **日志**：不应频繁出现资源等待/池耗尽/背压日志。
- **协议报文**：抓包观测背压征兆——R2T（数值 31h/iSCSI Ready To Transfer）下发变慢、窗口收缩、PDU 间隔拉大，是槽位/缓冲争用的外部旁证。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`（字段：用例编号/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论/覆盖目标/关联风险）。

- **用例雏形 1｜多流扩展无争用瓶颈**：预置多主机多连接 → 外部触发：逐步增加并发流满负荷加压 → 观测手段：性能统计（吞吐扩展曲线）+ CLI 占用均衡度 → 判据：吞吐线性升至硬件上限、占用均衡，提前平台期/单点满载判 FAIL。推导方法论：处理周期测试 / 数据组合测试（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜。
- **用例雏形 2｜共享池边界行为正确**：预置目标端 → 外部触发：并发 IO 数逼近并超过 tag 池/R2T 槽上限 → 观测手段：性能统计 + 抓包背压 + 日志 → 判据：达上限后有序排队/规范拒绝、无崩溃、无资源泄漏，超限行为符合规格。推导方法论：边界值分析（池容量边界）。关联风险：本透镜（并发/资源泄漏交叉）。
