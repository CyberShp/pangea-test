# 升级中断回滚透镜（DFX 维度：升级）

> 一句话：找"升级半途中断/回滚后状态不一致、灰度过程业务受损"的隐患——升级掉电/进程被杀/超时中断、失败自动回滚、灰度分批推进，都必须保证任何中断点可恢复、回滚后一致、业务不中断、不出现新老版本共存的错乱态。

## 风险机理

固件/软件升级是高危操作：过程涉及写入、切换、重启、双控倒换，任一步中断都可能留下不一致状态。灰度/分批升级期间新老共存又叠加兼容问题。缺口暴露为升级砖机、回滚不干净、业务中断、数据损坏。典型成因：
- **升级非原子/无检查点**：写入固件/切换配置的过程无事务与断点标记，中途掉电留下半新半旧。
- **回滚不完整/不幂等**：回滚只恢复一部分（固件回了、配置没回），或回滚重复执行破坏一致性。
- **中断点不可恢复**：某些中断点重启后既不能继续也不能回退（变砖）。
- **业务未平滑**：升级/倒换期间 IO 中断超出承诺窗口，未做连接保持/多路径接管。
- **灰度状态错乱**：分批升级中新老版本节点/控制器共存产生不兼容交互（与版本兼容交叉）。
- **升级前校验缺失**：未校验镜像完整性/版本合法性/前置条件即开始写入。

## 代码特征模式（给 excavator 的扫描指引）

以下为风险扫描剧本对本对象的 grep/阅读指令，命中即记 `文件:行号` + 机理（示例锚点均为示意）：
- **升级事务/检查点**：升级流程（`.*upgrade|.*firmware.*write|flash_|.*_activate|.*_commit`）是否有原子切换（双 bank/AB 分区）、断点标记、掉电保护。
- **回滚路径**：`rollback|revert|fallback|restore|.*_abort_upgrade` 是否覆盖升级已改动的全部项、是否幂等、是否可从任意中断点回退。
- **中断点枚举**：升级各阶段之间的可中断点——阅读状态推进，核对"每个中断点重启后能继续或能回退"（无死点）。
- **镜像/前置校验**：`verify|checksum|signature|magic|precheck|compatible` 在写入前的完整性/合法性/前置条件校验。
- **业务平滑/倒换**：升级期连接保持、双控倒换（`failover|takeover|graceful|drain`）是否让 IO 中断落在承诺窗口内。
- **灰度协调**：分批推进（`batch|canary|rolling|phase`）中的新老共存约束与兼容降级（交叉版本兼容透镜）。
- **免疫判断**：若对象不参与升级流程、无持久状态变更，则给"免疫理由"。

- （通用示意）固件升级写入新 bank 后、激活切换前掉电，无 AB 分区回退标记，重启后引导到半写 bank 变砖，无法自动回退到旧固件。

## 黑盒触发手段

存储领域的升级中断/回滚手段：
- **中断点注入**：在升级各阶段（写入中、激活前、重启中、倒换中）注入掉电/进程杀/网络断，逐点验证可恢复性。
- **回滚触发**：制造升级失败（坏镜像、前置不满足、中途报错）触发自动回滚，验证回滚干净幂等。
- **升级中带业务**：升级全程持续跑 IO，测量业务中断窗口是否在承诺内。
- **灰度/滚动**：双控/多节点分批升级，新老共存期间持续互通与跑 IO。
- **反复升降级**：多轮升级-回滚-再升级循环，验证不累积不一致、不泄漏。

## 观测判据（从 core/shared/观测手段目录.md 选手段）

判 PASS/FAIL 的外部现象（全部外部可观测）：
- **可用性/恢复**：任意中断点掉电重启后，设备能自动继续升级或回退到可用旧版本（不变砖）；无法启动或卡死 = FAIL。
- **CLI 回显**：`show version`/升级状态正确——成功后为新版本、回滚后为旧版本且完整可用；不应停留在半新半旧的错乱态。
- **业务中断窗口**：升级/倒换期间主机侧 IO 中断落在承诺窗口内（多路径接管）；超窗或 IO 失败 = FAIL。
- **数据一致性**：升级/回滚后主机读回校验数据一致、配置完整；不应半写或丢配置。
- **告警/日志**：升级过程与结果有规范告警/日志，失败回滚有明确记录与正确错误码；不应有 panic/引导失败以外的静默错乱。
- **反复升降级**：多轮后无资源/配置残留、无状态累积错乱。

## 用例骨架

> 格式见 `core/templates/黑盒用例.md`（字段：用例编号/用例名称/预置条件/外部触发手段/操作步骤/观测手段/观测判据/推导方法论/覆盖目标/关联风险）。

- **用例雏形 1｜升级中断点可恢复**：预置可升级版本 + 持续 IO → 外部触发：在写入/激活/重启/倒换各点注入掉电或断网 → 观测手段：可用性（重启后可继续或回退）+ CLI 版本状态 + 数据读回校验 → 判据：任一中断点不变砖、状态非半新半旧、数据一致，变砖或错乱态判 FAIL。推导方法论：状态转换（种子方法，升级状态机）/ 时间维度覆盖（时间维度 M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜。
- **用例雏形 2｜升级失败自动回滚干净**：预置目标端 → 外部触发：注入坏镜像/前置不满足触发回滚 → 观测手段：CLI 版本（回到旧版）+ 配置回显完整 + 数据校验 → 判据：回滚完整幂等、旧版本完全可用、无残留、无数据损坏。推导方法论：错误推测 / 端到端场景（M3 待补；过渡期按 `_selector` 规则回退种子方法并标注）。关联风险：本透镜（版本兼容性交叉）。
