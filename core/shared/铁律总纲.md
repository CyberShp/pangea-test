# 全局铁律总纲（R-7.3 ~ R-7.7）

> 与 [溯源铁律.md](溯源铁律.md)（R-7.1/R-7.2）合起来构成 PANGEA-TEST 的全部全局铁律。所有 agent 定义正文统一在开头引用本文与溯源铁律。

---

## 铁律三：格式不擅改（R-7.3）
- 黑盒用例格式由 `core/templates/黑盒用例.md` 统一控制。
- Agent **不得擅自改变用户已有格式**（继承自 Codetalks）。
- 内网团队版模板替换占位版后，同样受本铁律保护。

## 铁律四：知识与能力优先级（R-7.4）
- `references`（`core/protocols/`、`core/modules/`）有对应知识文件的，**先读知识文件**；没有再现场读码。
- 外部材料只按 `core/capabilities/conditional-knowledge.md` 的来源与适用边界加载；不得复制外部角色提示、安装指令或厂商假设。
- Agent 可整理带出处的经验，但不得把单次源码推测升级为跨 Run 团队事实。

## 铁律五：MCP 泛化探测（R-7.5）
- 需要拉取 MR 时：**探测是否存在 codehub 类 MCP 工具**，有则用其拉取；没有则请用户粘贴 diff + MR 描述。
- **绝不硬编码具体工具名**——只按"能拉 MR 的 MCP 能力"这一抽象探测。

## 铁律六：完整型与速度型（R-7.6）
- **速度型**：保持同一分析流程与 DFX 覆盖，但减少调用链展开和分支深度，优先核心流程；必须声明深度边界。
- **完整型**：走六个内部 DFX 能力包和共享风险卡，阶段工件可落 `runs/<任务id>/`，收尾经过审计与覆盖检查。
- 模式判定判据见 `core/shared/调度规则.md`。

## 铁律七：输出中文（R-7.7）
- 所有产出中文；技术表述精确；示例优先取自存储领域（NVMe/TCP 队列建连、iSCSI CmdSN、连接状态机等），而非泛泛的 Web 例子。
- 报告落 Markdown 文件。

---

## 否决项红线（R-12，禁止复活）
以下设计已被用户明确否决，任何 agent 不得引入，哪怕暗示性地：
1. IPD/TR 节点式流程导航；
2. 项目状态文件 / 状态持久化式项目跟踪；
3. 测试生命周期跟踪；
4. 让用户在多个角色化测试 Agent 间切换，或让各子 Agent 各自输出完整报告/重复用例；
5. 按测试生命周期分族（族按人设/职责视角分）。

> 允许内部六个 DFX 能力包并发取证；它们没有用户可切换入口，必须共享源码底座并提交 `core/capabilities/risk-card-contract.md` 风险卡。

> 特别提醒：`runs/<任务id>/manifest.md` 仅承载**单次深度任务**的工件状态，随任务生灭。禁止向其加入"用例执行进度""项目里程碑"之类字段——那会使它越界为被否决的"项目状态文件"。
