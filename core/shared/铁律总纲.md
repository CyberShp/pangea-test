# 全局铁律总纲（R-7.3 ~ R-7.7）

> 与 [溯源铁律.md](溯源铁律.md)（R-7.1/R-7.2）合起来构成 PANGEA-TEST 的全部全局铁律。所有 agent 定义正文统一在开头引用本文与溯源铁律。

---

## 铁律三：格式不擅改（R-7.3）
- 黑盒用例格式由 [../templates/黑盒用例.md](../templates/黑盒用例.md) 统一控制。
- Agent **不得擅自改变用户已有格式**（继承自 Codetalks）。
- 内网团队版模板替换占位版后，同样受本铁律保护。

## 铁律四：知识优先级（R-7.4）
- `references`（`../protocols/`、`../modules/`）有对应知识文件的，**先读知识文件**；没有再现场读码。
- 每次分析**收尾时询问用户是否回填知识**：
  - 透镜的"典型历史缺陷"栏；
  - `../protocols/`、`../modules/` 领域知识文件。
- 深度模式下，回填询问**写入报告末尾"待用户确认"节**，而非对话中提问（Task 子调用可能无法多轮交互，见 T-6）。

## 铁律五：MCP 泛化探测（R-7.5）
- 需要拉取 MR 时：**探测是否存在 codehub 类 MCP 工具**，有则用其拉取；没有则请用户粘贴 diff + MR 描述。
- **绝不硬编码具体工具名**——只按"能拉 MR 的 MCP 能力"这一抽象探测。

## 铁律六：双模式（R-7.6）
- **速度型**：族 agent 内联执行、不落中间工件（例外：MR 获取仍经 mr-reader，产出内联消费不落盘）。
- **深度型**：走能力 subagent、每步落交接工件（`runs/<任务id>/`，兼断点恢复）、收尾过 auditor + 覆盖审计。
- 模式判定判据见 [调度规则.md](调度规则.md)。

## 铁律七：输出中文（R-7.7）
- 所有产出中文；技术表述精确；示例优先取自存储领域（NVMe/TCP 队列建连、iSCSI CmdSN、连接状态机等），而非泛泛的 Web 例子。
- 报告落 Markdown 文件。

---

## 否决项红线（R-12，禁止复活）
以下设计已被用户明确否决，任何 agent 不得引入，哪怕暗示性地：
1. IPD/TR 节点式流程导航；
2. 项目状态文件 / 状态持久化式项目跟踪；
3. 测试生命周期跟踪；
4. 按视角拆多个特化挖掘 agent（挖掘用"单壳 × 剧本库"）；
5. 按测试生命周期分族（族按人设/职责视角分）。

> 特别提醒：`runs/<任务id>/manifest.md` 仅承载**单次深度任务**的工件状态，随任务生灭。禁止向其加入"用例执行进度""项目里程碑"之类字段——那会使它越界为被否决的"项目状态文件"。
