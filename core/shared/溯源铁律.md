# 溯源铁律（所有 agent 强制遵守）

> 本文是 PANGEA-TEST 的第一地基。任何 agent 的任何产出都必须通过本文的检查。auditor 的 `traceability` 与 `blackbox_executability` 两组检查直接以本文为准绳。
> 对应需求：R-7.1（溯源双轨制）、R-7.2（黑盒可执行性）。

---

## 铁律一：溯源双轨制（R-7.1）

**事实与推断必须走两条不同的轨道，永不混淆。**

### 轨道 A —— 事实
- 每一条陈述为"代码就是这样"的事实，**必须**给出证据锚点：
  - 代码事实：`文件路径:行号`（如 `net/nvme/tcp.c:1287`）；
  - 日志事实：日志原文位置（如 `log:12345`）+ 原文片段；
  - 报文事实：报文序号 + 字段（如 `pkt:88 NVMe/TCP C2HData`）。
- 给不出锚点的内容，**一律不得**写成事实——降级到轨道 B。

### 轨道 B —— 推断
- 任何"我认为/可能/推测"的内容，**必须**显式标注 `【推测】`，并附：
  - **依据**：基于哪些事实推出的；
  - **验证方法**：用什么**外部黑盒手段**可以证实或证伪（见铁律二）。
- 格式示例：
  > 【推测】异常路径 `nvmet_tcp.c:902` 在连接复位时可能漏释放 `cmd->req.sg`。
  > 依据：正常路径 `:870` 有 `sgl_free`，异常分支直接 `goto out` 未见释放。
  > 验证方法：反复建链/异常断链压测，观测内存占用是否单调上涨（`/proc/slabinfo` 或阵列侧内存告警）。

### 铁律三：无证据不下结论
- 既给不出事实锚点、也无法给出验证方法的判断，**不写入产出**，或明确写为 `open_question`（待补证），交由族 agent 或用户处置。

## 铁律二：黑盒可执行性（R-7.2）

**每一条测试用例、每一个验证方法，都必须是黑盒测试同学真能做到的。**

- **触发必须外部**：用协议报文构造、CLI 命令、故障注入、压力施加、配置变更等**外部手段**触发，禁止依赖"直接调用内部函数""设置内部变量"。
- **观测必须外部**：判 PASS/FAIL 只能依据**外部可观测现象**——协议报文、CLI 回显、告警、日志、性能统计、错误码等（手段目录见 [观测手段目录.md](观测手段目录.md)）。
- **禁止黑盒做不到的步骤**，典型反例：
  - ❌ "检查内部状态机变量 `sk_state` 是否为 `TCP_ESTABLISHED`" → 黑盒看不到内部变量；
  - ✅ 改为："观测该连接是否能正常收发 IO / CLI 查询连接状态是否为已建立 / 抓包确认三次握手完成"。

## 引用锚点写法约定
- 代码：`相对路径:行号` 或 `相对路径:起-止`。跨文件调用链用 `→` 连接。
- 对象 slug（用于 `runs/` 工件文件名）：仅取符号名/短名，`/`、`:`、空格替换为 `__`。
