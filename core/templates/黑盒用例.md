# 黑盒用例模板（通用占位版）

> 用途：族 agent 产出单条黑盒测试用例的统一格式。字段清单为架构 §4.5 的硬约束——**字段必须齐**。
> 溯源纪律：`外部触发手段` 遵守 R-7.2（触发必须外部）；`观测判据` 遵守 R-7.2（观测必须外部，禁止查内部变量）。
> `用例编号` 是 auditor `audit_opinion.checks.blackbox_executability.violations[].case_id` 的锚点（证据包 schema §4.3），**须全局唯一、可被引用**。

---

## 字段模板（单条用例）

- **用例编号**：`TC-<模块>-<序号>`（全局唯一；auditor case_id 引用此字段，填写指引：同一模块内递增，如 `TC-NVMET-TCP-001`）
- **用例名称**：一句话概括测什么（填写指引：动宾结构，如"反复建断链观测内存是否泄漏"）
- **预置条件**：执行前环境/配置/数据的既定状态（填写指引：写清组网、版本、初始资源计数等，保证可复现）
- **外部触发手段(R-7.2)**：用什么外部动作触发被测行为（填写指引：只能是协议报文构造/CLI 命令/故障注入/压力施加/配置变更；**禁止**"调用内部函数""设置内部变量"）
- **操作步骤**：有序步骤（填写指引：逐条编号，每步是黑盒同学真能执行的动作）
- **观测手段**：从 `shared/观测手段目录.md` 选取（填写指引：写明类别——协议报文/CLI 回显/告警/日志/性能统计/错误码——及具体观测点）
- **观测判据(PASS/FAIL)**：PASS 与 FAIL 各自的外部可观测判定（填写指引：**只能依据外部现象**；反例 ❌"内部 `sk_state==TCP_ESTABLISHED`"，正例 ✅"CLI `show connection` 状态为已建立"）
- **推导方法论**：引 `methods/`（填写指引：注明本例由哪种方法论推出，如 `methods/状态转换.md`、`methods/边界值分析.md`）
- **关联风险（可选）**：引 `lenses/` 透镜或 SFMEA 条目编号（填写指引：如 `lenses/资源泄漏.md` 或 `SFMEA-NVMET-TCP-003`；无则留空）

## 示例用例（存储领域·演示每字段怎么填）

- **用例编号**：`TC-NVMET-TCP-001`
- **用例名称**：NVMe/TCP 反复建断链观测控制器侧内存泄漏
- **预置条件**：阵列开启 NVMe/TCP 端口并映射 1 个命名空间；主机侧 `nvme-cli` 就绪；记录初始内存基线（阵列侧内存统计 / `/proc/slabinfo` 对应 slab 计数）。
- **外部触发手段(R-7.2)**：主机侧脚本循环执行 `nvme connect` 建链后立即 `nvme disconnect` 断链（外部 CLI 动作），并穿插 TCP 层异常断链（拔线/`iptables` 丢弃 RST）注入连接复位路径。
- **操作步骤**：
  1. 采集内存基线并记录连接计数（CLI `show connection`）。
  2. 循环执行 建链→下发少量 IO→异常断链，重复 10000 次。
  3. 每 1000 次采集一次内存统计与连接计数。
  4. 循环结束后静置 5 分钟，再采集一次（排除延迟回收）。
- **观测手段**：性能统计（阵列侧内存占用统计接口）+ CLI 回显（`show connection` 连接计数）+ 告警（内存水位告警）。
- **观测判据(PASS/FAIL)**：
  - **PASS**：内存占用在多轮建断链后回落至基线附近（波动在正常缓冲范围内）；连接计数随建/断链正确增减、最终归零；无内存水位告警。
  - **FAIL**：内存占用随建断链次数单调上涨且静置后不回落；或连接计数只增不减（残留连接）；或触发内存水位告警。
  - （判据均为外部可观测，未依赖任何内部变量。）
- **推导方法论**：`methods/状态转换.md`（建链↔断链↔异常复位的状态迁移覆盖）。
- **关联风险**：`lenses/资源泄漏.md`；对应 `SFMEA-NVMET-TCP-003`（异常断链路径漏释放 `cmd->req.sg`）。
