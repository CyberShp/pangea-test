# PANGEA-TEST 内网验收清单

> Architecture v2 清单，更新于 2026-08-05。旧 Dispatcher、三族 Agent、`module-full-analysis` 和 `workspace/outputs` 协议均已退役，不得在内网恢复。

## 首次启用

- [ ] 在仓库根目录启动 OpenCode/CodeAgent，确认 Tab 中唯一可见主入口是 `pangea-test`。
- [ ] 确认六个 DFX Agent、`mr-reader`、`code-excavator`、`auditor` 均隐藏，且只能由主 Agent 调用。
- [ ] 执行 `/initial`，核对 `pangea-data/`、Python 3.9+、Git、GitNexus、文档转换能力和降级说明。
- [ ] 确认 `pangea-data/repositories/` 中每个仓都是独立 Git 工作树根目录；符号链接、父仓普通子目录和脏仓必须被拒绝或跳过。
- [ ] 验证当前内网 MR MCP 能返回 MR 描述、diff、分支和确定 commit；记录实际工具名与认证前提。

## 两条工作流

- [ ] `/mr-regression`：用真实 MR 验证 commit 固定到 Run 内只读快照，源仓 HEAD、分支、索引和工作区前后不变。
- [ ] `/mr-regression`：验证原场景回归、改动功能、影响链、异常与恢复四类基线均出现；无快照时审计和交付必须被阻止。
- [ ] `/module-analysis`：验证完整型会运行六维扫描、相关专项深挖、内部 SFMEA、场景和用例，中间不逐阶段停问。
- [ ] `/module-analysis --fast`：验证流程与六维覆盖不变，只减少调用链和分支展开深度，并明确深度边界。
- [ ] 用跨仓卡件驱动/微码样本验证：可用仓继续分析，缺失仓进入覆盖缺口，不伪造结论。

## 团队资料

- [ ] 将团队 Word、Excel、PPT、PDF、Wiki 导出件放入 `pangea-data/inbox/`，验证 new session 增量转换、锚点、hash 去重和语义分类。
- [ ] 对不支持视觉的模型确认图片被标为未解析视觉证据；支持视觉的模型确认图片引用可追溯到原文档与页/Sheet/幻灯片。
- [ ] 导入存量用例、版本报告、历史缺陷和经验文档；抽样检查模型分类不会被当作来源事实，报告证据仍回到材料锚点。
- [ ] 用团队版用例字段、术语和严重度样本校准风险卡与报告，但不得放宽黑盒优先、插桩不产代码和禁止白盒用例的边界。

## 工具与容量

- [ ] 记录内网 GitNexus 版本、首次索引时间、增量检测能力、典型仓磁盘占用和失败降级表现。
- [ ] 测量六个子 Agent 并发上限、返回体量和 200k/4096 模型约束，确定完整型与速度型的批大小。
- [ ] 仅通过 `/setup-tools` 评估内网可获得的 clang-tidy、cppcheck、Semgrep 或 CodeQL；不得自动联网安装或使用容器。
- [ ] 验证长任务 checkpoint、风险账本、审计整改和跨 new session 恢复；未完成 Run 的 MR 快照不得因时间老化被清理。

## 交付验收

- [ ] `report.md` 与单文件离线 `report.html` 内容一致，包含固定十章、搜索/筛选、风险与用例双向跳转。
- [ ] 在隔离网络或浏览器请求审计下打开 HTML，确认没有 CDN、外链脚本、外部 SVG URL 或控制台错误。
- [ ] 抽样检查代码地图、流程和分支中的白盒术语都有测试解释；风险、场景和用例使用黑盒语义，少量灰盒只描述诊断或控制时窗。
- [ ] 用公开缺陷样本和内网已知问题分别做盲测，评分覆盖广度、证据、因果链、触发/观测/恢复、严重度与黑盒纯度。

## 后续能力

- [ ] 收集首轮用户反馈后校准六个 DFX 能力包和资源规格/泄漏专项，不新增角色型用户入口。
- [ ] 两条首版工作流稳定后，优先设计补丁测试策略；在细节冻结前不新增正式命令。
